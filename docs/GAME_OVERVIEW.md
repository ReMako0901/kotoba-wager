# ゲーム概要

## 作るもの

仮称「ことばの取引所」（API側表記は「言葉の取引所 — Prototype B」）。短い文章の中から、プレイヤー自身が失ってもよい／守りたい意味を選び、欲しい表現・出来事と引き換えに賭ける創作ゲーム。現金、換金、現実の賞品はない。

勝てば賭けた意味が残り、選んだ報酬が物語に加わる。負ければ選んだ意味が消え、成立しなくなった依存描写も必要な範囲で変わる。単語を消して穴を作るだけではない。小さな喪失なら小さく、大きな意味の喪失ならその依存範囲まで変わる。

例：「黄色い日傘」の「黄色い」を失っても、日傘や持ち主まで消さない。「代金の」を失っても、配達員・ピザ・注文者まで消さない。人物そのものを失えば、その人物を前提とする出来事まで変わる場合がある。

## 現在の1プレイ

1. 保存済み開始文からランダム3件を全文表示。リロール可能。
2. 1件を選択。分割・選択可否・報酬準備はローカルで行い、ここではAI呼出0回（APIキー設定の確認自体は行う）。
3. 報酬3択をポップアップで先に選ぶ。
4. 本文の枠があるコマをタップ。選択解除・複数選択可能。
5. 要求個数ちょうどなら実行可能。現在の仮設定は1個／2個／3個。同じ重みであり点数計算はしない。
6. サーバーが一度だけ抽選して保存。現在の勝率仮設定は50%。
7. Geminiが選んだ原文の意味を解釈し、確定勝敗に沿う部分編集を生成。
8. 検査に通れば結果表示、次ラウンドへ。失敗なら本文を残し、同じ勝敗で手動再試行。

現在は終了回数・エンディングを実装しておらず、繰り返し取引するプロトタイプ。

## コマと価格

「単語」はUI上の意味ある短いまとまり。辞書上の一単語や文法上の文節と常に一致するわけではない。助詞・助動詞を含んでよい（「私の」「晴れた日に」「拍子抜けして」等）。

枠のない接続表現・副詞・一般的な動作は本文に残る。現行の形態素ルールとゲーム用辞書で可否を決め、AIの採点失敗で「？」を付けて選択を塞がない。選べるコマはすべて同じ1個。

別位置の同じ語もそれぞれ1個として選べる。同じIDの二重選択、古い本文版、重なる範囲、不正個数は拒否。意味が同じ選択を後でまとめても支払ったコマ数は変えない。

## 報酬の仮設定

|必要数|序盤|中盤|後半|
|---|---|---|---|
|1個|ちょっと名文|いい感じの空気|ひとことの魔法|
|2個|ラッキーな発見|うれしい知らせ|まさかの正体|
|3個|まさかの出来事|新しい出会い|新しい行き先|

2ラウンドごとに内容の段階が変わり、3段階目で固定。編集規模は要求個数側の `change_scale`。ラウンド段階 `tier` だけで全報酬の改変量を大きくしない。選択可能数が不足すると成立する報酬だけを表示し、要求数を勝手に値引きしない。これらの名称・数・数値は正式決定ではない。

## 体験の方針

- 白黒基調、文章が主役。スマートフォン縦画面・タップ前提。
- 報酬を決めてから賭ける語を選ぶ。なるべく1画面で完結し、長い場合は本文領域内でスクロール。
- 短くポップな文章。毎回全面改稿・重い悲劇・脈絡のない道具の擬人化は避ける。
- 自分が望む作品へ変えることが中心。魔女の好みへ最適化するゲームではない。
- 音楽版の「ギャンブルメロディーメーカー」は発想の前史。現在の実装は文章版。

## 研究として確かめたいこと

金銭の同じ尺度に揃わない「自分が残したい内容」と「欲しい新しい内容」の取引で、何を手放し、どう選択・解釈するかを観察する構想。学術的新規性・効果・面白さはまだ実証していない。完成済み研究や有効性を断定しない。

以前のA案は矛盾を補完しない詩的な短文、B案は喪失に依存した意味を再構成する文章。現在はB系を実装している。A/B両モードや参加者実験は未実装。
