# ゲーム概要

## 作るもの

「ギャンブルライティングメーカー(仮称)」。短い文章の中から、プレイヤー自身が失ってもよい／守りたい意味を選び、欲しい表現・出来事と引き換えに賭ける創作ゲーム。現金、換金、現実の賞品はない。

勝てば賭けた意味が残り、選んだ報酬が物語に加わる。負ければ選んだ意味が消え、成立しなくなった依存描写も必要な範囲で変わる。単語を消して穴を作るだけではない。小さな喪失なら小さく、大きな意味の喪失ならその依存範囲まで変わる。

例：「黄色い日傘」の「黄色い」を失っても、日傘や持ち主まで消さない。「代金の」を失っても、配達員・ピザ・注文者まで消さない。人物そのものを失えば、その人物を前提とする出来事まで変わる場合がある。

## 現在の1プレイ

1. 保存済み開始文100件から最大3件を全文表示。リロールするか、20〜100文字の本文を入力して開始できる。自作文は賭け対象が3個以上必要。
2. 1件を選択。保存済みの区切りと選択可否を読み込み、報酬を準備する。ここではAI呼出0回（APIキー設定の確認自体は行う）。
3. 報酬3択をポップアップで先に選ぶ。
4. 本文の赤い線があることばを、報酬が要求する1個／2個／3個ちょうど選ぶ。どれも同じ重みで、点数計算はしない。
5. 必要なことばがそろったら、初心者／上級者を切り替え、ギャンブルを選ぶ。
6. ゲームの選択と同時に開始し、上級者向けは開始時に勝敗や演出を保存する。初心者向けは決着した操作を保存してから物語を生成する。
7. プレイヤーのSTOP・HIT／STAND・カードの絞り／公開、初心者向けの実操作で進める。無操作では決着させず、スキップも明示操作だけ。その裏でGeminiが意味を解釈し、勝敗と強さに沿う編集案を生成する。
8. 反映ボタンを押し、新しい原稿用紙が上に重なる形で検査済みの本文を読む。結果と履歴は最新の原稿を先頭に、前後に1枚ずつめくって過去の本文を読む。横書きの比較は行わない。生成が失敗した場合は同じ勝敗で補完する。

ゲーム画面はナビ、コンパクトなアノマ、メタ情報、原稿または盤面、下端のアクションバーで構成する。結果の「どこが変わった？」は同じ原稿上で差分を強調する。タイトルからは新規プレイを開始し、プレイは同じ訪問中に進める。レイアウトの正本は [UI_LAYOUT.md](UI_LAYOUT.md)。

## ギャンブルと変化の強さ

|ゲーム|決着時の勝率|変化の強さ|
|---|---|---|
|じゃんけん|50%（決着時）|一手ごとに勝ち33%、負け33%、あいこ34%。勝敗ともに2。|
|カード当て|当てずっぽうで1/3|8回の高速シャッフル後に1枚を選ぶ。勝ち3、負け4。|
|一発サイコロ|50%|4〜6で勝ち、1〜3で負け。1・6は8、それ以外は1。|
|スロット|50%|当たりの内訳：ベル65%（1）、スイカ25%（2）、REG5%（4）、BIG5%（8）。ハズレは2。|
|ブラックジャック|60%|勝っても負けても1。最初は両者2枚、ディーラーは1枚公開。HITで1枚追加し、STAND後はディーラーが17以上で止まる。初手のナチュラルは約1割。開始時に確定した勝敗はどの操作順でも同じ。|
|バカラ|45%|勝敗共通の点差分布：9点20%（10）、7〜8点25%（9）、4〜6点25%（2）、1〜3点30%（1）。|

バカラはプレイヤー側。各配りの5%でタイとなり、同じベットで配り直す。タイ以外では勝ち45%・負け55%なので、配り直し後の最終勝率は45%。タイの手も開始時に用意する。カードの引き方は[Singapore GRAのバカラ規則](https://www.gra.gov.sg/docs/default-source/game-rules/rws/baccarat-games/rws-game-rules---commission-baccarat-v4.pdf)を参照。抽選確率はゲーム独自。

強さは報酬の価格と独立し、勝利ではポジティブ、敗北ではネガティブな展開の度合いを指定する。強さ1は小さな変化、強さ8〜10は物語の行く先を変える展開を狙う。強さの体感はプレイ評価で確認する。

世界観とストーリーの正本は [STORY_DESIGN.md](STORY_DESIGN.md)。アノマは言葉の個数だけを評価し、人間にとっての言葉の主観的価値とのズレを表す。S1で両モード共通のオープニングと結果反応を実装。S2＋S3をローカル実装。規定回数（既定5〜8回、事前非公開）に達すると脱出／継続を選べる。継続後も各結果で脱出でき、言葉の個数の最終差分によるノーマルエンディングへ進む。公開版への反映と検証状況はSTATUSを参照。

## コマと価格

「単語」はUI上の意味ある短いまとまり。辞書上の一単語や文法上の文節と常に一致するわけではない。助詞・助動詞を含んでよい（「私の」「晴れた日に」「拍子抜けして」等）。

賭け対象は名詞的な核と対象を特定する修飾。「黄色い」「日傘」は別コマのまま両方選べる。枠のない接続表現・程度や様態の副詞類・形式名詞的な軽いコマ・一般的な動作は本文に残る。場面を担う動詞のまとまりは従来の線引きを維持する。現行の形態素ルールとゲーム用辞書で可否を決め、AIの採点失敗で「？」を付けて選択を塞がない。選べるコマはすべて同じ1個。

別位置の同じ語もそれぞれ1個として選べる。同じIDの二重選択、古い本文版、重なる範囲、不正個数は拒否。意味が同じ選択を後でまとめても支払ったコマ数は変えない。

## 報酬の候補プール

報酬は表現系（新しい要素を足さず既存の描写を深める）と展開系（新しい要素を1つ追加し物語を前へ進める）の2系統。以下の従来9種を各セルに残し、各セルの両系統に候補を用意する。追加候補は「鮮やかな比喩」「心の声」「次の場面へ」「新しい場所」「誰かの約束・目的」「関係の変化」「小さな危機の接近」。要求数と段階が上がるほど、説明上の対象を一瞬から物語の行く先まで広げる。

通常は各価格から1件の3択とし、系統を表示する。成立する候補には展開系を最低1件含め、提示内容をラウンド状態として保存する。再読み込みや再送では変わらない。負け側には進展報酬を付与しない。詳細は[報酬仕様](PHASE4_REWARDS.md)。

|必要数|序盤|中盤|後半|
|---|---|---|---|
|1個|ちょっと名文|いい感じの空気|ひとことの魔法|
|2個|ラッキーな発見|うれしい知らせ|まさかの正体|
|3個|まさかの出来事|新しい出会い|新しい行き先|

2ラウンドごとに内容の段階が変わり、3段階目で固定。新フローでは編集規模をギャンブル結果の強さで調整する。報酬の要求個数・ラウンド段階とは別の値。選択可能数が不足すると成立する報酬だけを表示し、要求数を勝手に値引きしない。これらの名称・数・数値は正式決定ではない。

## 体験の方針

- 白黒基調、文章が主役。スマートフォン縦画面・タップ前提。
- 報酬を決めてから賭ける語を選ぶ。なるべく1画面で完結し、長い場合は本文領域内でスクロール。
- 短くポップな文章から始める。弱い変化では局所編集を保ち、強い変化では賭けに結びつく大きな転換を許す。
- 自分が望む作品へ変えることが中心。魔女の好みへ最適化するゲームではない。
- 音楽版の「ギャンブルメロディーメーカー」は発想の前史。現在の実装は文章版。

## 研究として確かめたいこと

金銭の同じ尺度に揃わない「自分が残したい内容」と「欲しい新しい内容」の取引で、何を手放し、どう選択・解釈するかを観察する構想。学術的新規性・効果・面白さはまだ実証していない。完成済み研究や有効性を断定しない。
