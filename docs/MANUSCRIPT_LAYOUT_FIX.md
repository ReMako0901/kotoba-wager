# 原稿用紙レイアウトの修正（2026-11-18、ユーザーのプレイ確認）

結果画面の原稿表示が崩れているというユーザーの指摘への対応。
PHASE4_PLAYTEST_FIXES_2 §2 の「行数を本文量から決める」方式は
本仕様で置き換える（あの方式が今回の崩れの原因）。

## 症状（ユーザーのスクリーンショット）

- 原稿が3行分ほどしか表示されず、最下行の文字が枠で切れている
- 本文の途中に空きマスが混ざり、文字がマスを使い切っていない
- 肝心の「変わった言葉とその前後」が見えない
- 原稿の表示面積が狭い

## あるべき姿

1. **縦は固定、横だけスクロール**：原稿の行数は本文量から
   決めない。行数は固定値（10行）とし、CSS の一箇所で定義
   する（--paper-rows）。マスの大きさ（--cell-size: 32px）は
   従来どおり単一定義で固定。本文が増えたら列が増えて横に
   伸び、表示領域は横スクロールのみ（overflow-x のみ許可、
   縦スクロールは禁止）。全行が常に見え、文字が枠で切れる
   ことはない
2. **マスを正しく使う**：文字は最初のマスから連続して埋める。
   本文の途中に空きマスを作らない（本文の後ろの余白はよい）。
   句読点の行頭回避など既存の原稿用紙ルールは維持してよいが、
   それで空きマスや見切れを作らない
3. **変わった箇所が見える**：結果画面では、最初に変わった
   箇所とその前後が初期表示で見える位置に横スクロールを
   合わせる。差分のハイライトは維持する。全文は横スクロール
   で端から端まで読める（見切れて読めない部分を作らない）
4. **表示面積を広げる**：行数固定（10行）により原稿の高さを
   確保する。言葉選択・結果・履歴のすべての原稿表示に同じ
   幾何を適用する

## テスト観点

- 行数が本文量によらず固定値であること（--paper-rows の
  動的計算が残っていないこと）
- 長い本文でも列数が増えるだけで、全文字が配置されること
- 本文の途中に空きマスができないこと（配置の連続性）
- 表示領域のスクロールが横のみであること（CSS の確認）
- 結果画面で変わった箇所が初期表示範囲に入ること
