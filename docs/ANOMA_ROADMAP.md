# アノマ実装ロードマップ（キャラクター演出トラック）

アノマの画像・瞳文字・アニメーションを段階的に実装するための
計画。正本は [ANOMA_CHARACTER.md](ANOMA_CHARACTER.md)（キャラ
設定）と [STORY_DESIGN.md](STORY_DESIGN.md)（ストーリー設計）。
ストーリー進行のフェーズ（S1〜S5）とは別トラックで、合流点は
「アノマの表示枠」と「反応イベント」。

Phase 4 までで、アノマがゲーム内で反応する実用版を完成させる。
Phase 5 以降は品質向上のための追加実装と区切る。

## フェーズと完了条件

| Phase | 内容 | 完了条件 |
| --- | --- | --- |
| 0 | 実装環境の確認：既存ゲームの構成、画面、勝敗処理、画像表示方式を調査し、変更箇所を決める | 既存コードの変更箇所が特定できている |
| 1 | 基準画像の完成：白黒、バストアップ、片目の漢字、取り消し線付き名札を確定 | アノマの基準画像1枚が確定している |
| 2 | 静止画のゲーム実装：背景透過、適切な配置、スマホ対応。原稿用紙 UI にアノマを組み込む | ゲーム画面に静止画が正常表示される |
| 3 | 瞳文字の動的制御：言葉の増減で漢字をランダム変更。重大イベントでは両目に表示 | **中止**（2026-11-18 ユーザー判断：現在の画像サイズでは瞳に文字を収めるのが厳しいため取りやめ） |
| 4 | 基本アニメーション：瞬き、微笑み、口パク、わずかな揺れ。画像差分と JavaScript で実装 | 瞬き・表情差分が動作する |
| 5 | AI アニメーションの導入：LivePortrait 等を試し、必要に応じてパーツ分割・Live2D 化 | AI 由来の自然な動きを組み込める |
| 6 | 演出統合・最終調整：6ゲーム共通の演出、グリッチ、脱出演出、端末ごとの表示と負荷の調整 | すべてのギャンブルとエンディングで演出が動作する |

## Phase 3 の固定ルール（決定済み）

- 瞳文字の対応は ANOMA_CHARACTER §3 と STORY_DESIGN §7 の
  通り（通常＝片目「言」、獲得＝得・増・生・添、喪失＝失・欠・
  亡・消、重大改変＝両目に異常系＋グリッチ、イベント＝続・賭・
  帰・終）
- **瞳文字の変更を各ギャンブルに個別実装しない。** 6種類の
  ゲームの結果を共通イベントとして受け取る構造にする。種目を
  追加してもアノマ側を変更しなくて済むようにする
- 共通イベントの源は、ストーリートラック S1 で保持する
  「反応種別」（通常／獲得／喪失／改変／連続勝敗）を想定する

## 共通要件

- 白黒のみのビジュアル。原稿用紙風 UI との統一
- 胸元の名札には、横線で取り消された「アノマ」を表示
- 通常時は片目だけに漢字を表示
- 重大改変時は両目に漢字とグリッチ演出を表示
- アニメーションの有無によってゲームの進行が変わらないこと
- 画像やアニメーションが読み込めない場合は静止画表示に
  フォールバックする
- データ収集、ギャンブル結果、言葉の保存処理に影響を与えない
- 既存の6種類のギャンブル、勝敗処理、言葉の改変処理は維持
- 画像素材は必要になった段階で用意する。LoRA 学習は初期
  フェーズでは実施しない
- 各フェーズの実装後に動作確認を行う

## Phase 0 の作業（調査のみ）

1. 現在のプロジェクト構成を調査する
2. ゲーム UI の構成と使用技術を確認する
3. 各ギャンブルの結果が確定する処理を特定する
4. アノマの画像・アニメーションを組み込む場所を提案する
5. Phase 1〜6 の実装箇所と依存関係を整理する
6. 現在の進捗と次の作業を文書に記録する

この段階では既存コードの機能変更と画像生成を行わない。
調査結果は ANOMA_PHASE0.md に記録する。S1（台詞基盤）の
実装が完了した時点のコードを対象に調査する。
