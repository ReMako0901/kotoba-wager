# Phase 4 仕様： 全文レビューの強化と整合性の数値化

作成： 2026-11-17（Muse）。Phase 4「文章全体の違和感をなくす
処理の強化」と、ゼミ指摘「整合性を数値化、減点方式」への対応。
Phase 2 の検証で観察された最終確認の却下（ReviewRejected、
理由未特定）とも地続き。

## 1. 目的

- 3段階生成の最終レビューを、感覚的な可否から **減点方式の
  チェック** に変え、却下理由を特定可能にする
- 生成文の整合性を検査する仕組みであり、ゲーム内の点数制とは
  完全に切り分ける

## 2. 仕様

### 2.1 減点チェック

- レビューは満点から減点する方式で整合性を評価する。減点項目の
  例（実装時にプロンプトとコードへ落とす）：
  - 失われた意味への言及が残っている（喪失の不整合）
  - 人物・場所・物の設定が前文と矛盾する
  - 時制・視点・文体の不意な切り替わり
  - 文同士のつながりの破綻、指示語の宙吊り
  - 賭けた言葉の意味の扱いが勝敗結果と食い違う
- 合計減点がしきい値を超えたら却下し、**どの項目で何点引いたかを
  理由としてログに残す**（却下理由の特定が目的。Phase 2 で
  未特定だった ReviewRejected の観察を続ける）
- しきい値と配点は定数として一箇所にまとめ、調整可能にする

### 2.2 位置づけの制約

- この数値は生成文の検査専用。プレイヤーに見せない。報酬の
  個数方式や選択可否の判定には使わない
- 却下時の扱いは現行どおり（同じ勝敗のまま固定の代替文で完了。
  再抽選しない）

### 2.3 実装の置き場

- 既存の3段階（意味解釈→編集→全文レビュー）のレビュー段階を
  拡張する。段階の増設はしない
- モデル呼び出し回数は増やさない（レビューのプロンプトと
  応答形式の変更で実現する）

## 3. 検証の範囲（重要）

- この環境には Gemini のキーが無いため、**実 Gemini での検証は
  今回行わない**。単体テスト（モデル応答を差し替えたテスト）で
  減点集計・しきい値判定・理由ログ・代替文への落ち方を確認する
- 実 Gemini 検証は未実施として STATUS に明記する

## 4. テスト観点

- 減点項目ごとの集計が正しいこと
- しきい値の前後で可否が切り替わること
- 却下時に理由（項目と点数）がログへ残ること
- 却下時も勝敗と代替文完了の既存挙動が変わらないこと
- 呼び出し回数が増えていないこと
