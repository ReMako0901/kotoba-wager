# アノマ演出トラック Phase 0：調査報告（2026-11-18）

[ANOMA_ROADMAP.md](ANOMA_ROADMAP.md) の Phase 0。既存コードの
機能変更はしていない。対象はストーリートラック S1（台詞基盤・
アノマ表示枠）が着地した時点のコード。

## 1. プロジェクト構成

- フロントエンド：React 19 + TypeScript + Vite。GitHub Pages
  から配信。CSS は手書き（Tailwind 等は使っていない）
- バックエンド：Python / FastAPI。Cloud Run + Firestore。
  抽選と勝敗はサーバー側で確定して保存され、フロントは結果を
  受けて演出する（再抽選はしない）
- 画像素材：`frontend/public/` 配下に置く方式（既存は
  cards／slot-symbols）。キャラクター画像はまだ無い

## 2. UI の構成と、アノマの現在位置

- 画面遷移は App.tsx が管理（タイトル／物語選択／ゲーム）
- ギャンブルの操作画面は上級が GamblePlay.tsx、初心者が
  BeginnerPlay.tsx。結果の表示は両モードとも App 側の共通
  結果画面に集約されている
- S1 で追加された受け口：
  - `Anoma.tsx` の `AnomaFrame`：名前（名札モチーフの取り消し
    線付き）＋台詞の枠。`portrait` スロットがあり、キャラ画像を
    後から差し込める。枠には `data-reaction` 属性で現在の
    反応種別が出ている
  - `scenario.ts`：台詞データと反応種別の決定（獲得／喪失／
    改変／連続勝敗／通常）。台詞の選択はここに一元化されている
  - `anoma.css`：枠の体裁（純白・明朝・白黒＋赤）

## 3. 結果が確定する処理（共通イベントの源）

- 勝敗そのものはサーバーが確定し、セッションの取引
  （transactions）に保存される。フロント側の確定点は
  「取引が committed になり結果画面が表示される」ところで、
  6種＋初心者3種のすべてが同じ結果画面に合流する
- したがって Phase 3 の瞳文字は、ギャンブルごとに実装せず、
  結果画面の `AnomaFrame` と `scenario.ts` の反応種別を
  そのまま共通イベントとして使える。種目が増えてもアノマ側の
  変更は不要な構造になっている

## 4. フェーズごとの実装箇所と依存関係

- **Phase 1（基準画像）**：ユーザーが用意する素材。受け入れ先は
  `frontend/public/anoma/` を想定。バリエーション（設定表 §6）
  ごとにファイルを分け、顔立ち・構図・名札位置を統一する
- **Phase 2（静止画統合）**：`AnomaFrame` の `portrait`
  スロットに画像を差し込む。配置と大きさは `anoma.css`。
  スマホ縦画面が主対象。画像が読み込めない場合は枠と台詞
  だけで成立する（現在の状態がそのままフォールバックになる）
- **Phase 3（瞳文字連動）**：反応種別→瞳文字の対応表を
  `scenario.ts` 側に持ち、表示は画像差し替え（Phase 1 の
  バリエーション画像）または画像への重ね表示のどちらか。
  重大改変時は両目＋グリッチ（CSS のグリッチ表現を想定）
- **Phase 4（基本アニメーション）**：瞬き・口パク・揺れは
  画像差分＋CSS／JS で `AnomaFrame` 内に閉じて実装する。
  アニメーションの有無でゲーム進行が変わらないこと、
  prefers-reduced-motion で静止画に落ちることが条件
- **Phase 5（AI アニメーション）**：LivePortrait 等の検証は
  別途スパイクとして切り、採用可否を判断してから組み込む。
  生成物が重い場合はスマホ負荷の観点で不採用もあり得る
- **Phase 6（演出統合）**：脱出・継続・エンディングの画面は
  ストーリートラック S2／S3 で生まれる。その画面の
  `AnomaFrame` にイベント系の瞳文字（続・賭・帰・終）と
  グリッチを接続する。全ギャンブル共通の確認は結果画面の
  集約構造により一箇所で済む

## 5. 進捗と次の作業

- Phase 0 はこの報告で完了（完了条件：変更箇所の特定）
- 次は Phase 1（基準画像の確定、ユーザー側）と、並行して
  ストーリートラック S2（規定回数と脱出／継続の選択）
- Phase 2 以降は Phase 1 の素材が揃ってから着手する
