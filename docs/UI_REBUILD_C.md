# UI全面再構築 C案：手帳（革の手帳のページ）

ユーザーが2026-11-25に「UIを完全に一から作り直して。既存の型の流用禁止」と指示。
本書はC案の仕様。作業ブランチは rebuild-c（このツリー）。現行の公開版は main に残る。

## コンセプト

画面は「開いた革の手帳」。全画面が手帳のページとして組まれ、革の縁・縫い目・栞のリボンが
画面の枠になる。世界は紙と革と、ページの上に置かれた実物だけ。
フェルトの卓、金のプレート、ディーラー対面の文法は持ち込まない。
色は革の茶、紙のクリーム、インクの色、栞の赤。

- タイトル：手帳の表紙。革に型押しされた題字、ゴムバンドの意匠。
- 物語選択：見出しタブ（インデックス）の付いた目次ページ。3冊はタブ付きの一覧行として並ぶ。
- 報酬選択：ページに貼られた3枚のメモ／付箋として提示する。
- 言葉選択：手帳の方眼ページに書かれた本文。原稿のマス目は方眼罫として表す。
- ギャンブル選択：種目はページに書かれた一覧。初心者／上級者は栞やタブの位置で切り替える。
- ギャンブル盤面：開いた手帳の上に置ける実物だけ。札＝本物のトランプ、賽＝賽、
  スロット＝紙の回転盤や小さな機械式カウンタのような、日記小物として置ける物に置き換える。
  ブラックジャック／バカラ＝ページの上に配られたトランプ。物には柔らかい影を落とす。
- 結果：改稿ページが主役。版数と勝敗はページ隅の小さな記録欄のように置く。

## アノマの置き方

- 常時表示だが主役にしない。手帳に挟んだ白黒写真（白枠の写真カード、少し傾けて
  テープで留めた風）として、ページの隅に固定する。顔全体が見える大きさ。
  プレー画面では画面高さの25%以下を目安にする。
- 顔の領域（目の高さから顎まで、顔の幅）に、本文・盤面・ボタン・タグを一切重ねない。
- 台詞は手書き風のメモとして、写真の近くかページの余白に置く。プレート状の箱にしない。
- 肖像に blur を使わない。常にはっきり見える。

## 共通の不変条件（A・C共通、違反禁止）

1. ゲームのルール・流れ・確率・抽選・保存・バックエンド・APIは変更しない。
   流れは 報酬3択→言葉選択→ギャンブル選択→開始→結果反映 の順を厳守。
2. 原稿の力学は維持：マス32px、10行、文字は先頭から連続して詰める、横スクロールのみ、
   紙めくりは角つかみの斜めドラッグ（右下→過去、左上→未来）。
3. ギャンブルは全てプレイヤー自身が操作する。自動進行タイマーは置かない。
4. メタ情報は一切表示しない：勝率、強さ、改変の大きさの説明、遊び方文、ボタンの下の状態文、
   賭け内容のまとめ箱。出すのはアノマの台詞、ボタンの名前、種目名、集計の数字、物語の本文だけ。
5. アノマは全場面で常時喋る。場面台詞プール（sceneDialogue.ts）と
   確定台詞の優先順位は変えない。表情プール（scenario.ts）も変えない。
   異常（怖い顔）と怒り系の表情は使わない。口パク（talk差分）・瞬き・呼吸の仕組みは残す。
6. つづき機能は作らない。
7. 画面の収まり：393×681（ユーザーの実機相当）で、主ループの全画面が
   ページスクロールなし・主領域の内部スクロールなしで完結する。物語選択は3冊とも見える。
   390×844でも崩れず、デスクトップ幅でも構成が壊れない。
8. 実装の作法：新しい体裁CSSファイルを作り、旧体裁CSS（anoma.css、layout.css、
   table-finish.css 等の見た目部分）は import から外して置き換える。上書きの継ぎ当てにしない。
   原稿の力学に関わるCSSは効果を保ったまま新しい見た目に組み替える。
   JSXのラッパー構造は自由に変えてよいが、ゲームロジック・状態・API呼び出し・
   ギャンブルの操作ハンドラの意味は変えない。

## テストと作業メモ

- フロントテストは repo ルートから `node --test frontend/tests/<file>` で回す。
  行動・ロジックのテストは必ず通す。旧体裁そのものを検証しているテスト
  （旧CSSの規則やセレクタへの断定）は、新体裁に合わせて更新・削除してよい。
  ただし変更したテストは全て docs/WORKLOG_C.md に理由つきで列挙する。
- docs/WORKLOG_C.md を作業しながら随時更新する。別のモデル（GO）が引き継げるよう、
  決定事項、変更ファイル、テスト変更一覧、完了分、残作業（順序つき）、落とし穴を書く。
  途中で止まるときは、引き継ぎ欄を最新にしてから止まる。
- ビルドやテストがサンドボックスで止まったら、繰り返し時間を溶かさず、
  その旨を作業メモに書いて先へ進む。検証は Muse が行う。
- git pull は不要（このツリーが最新）。コミットはしない。作業ファイルの残骸を残さない。
- CHANGELOG.md と STATUS.md の更新は統合時に Muse が行うので触らない。
