# Phase 4 仕様： 物語の変遷ビューと変化の前後表示

作成： 2026-11-17（Muse）。ゼミでの指摘（2026-11-13）への対応：
「変わったところを見せる」「最初と最後で比べられる」「ページを
またがずセットに」「変遷を辿れると面白い」。

## 1. 目的

- 取引のたびに本文がどう変わったかを見えるようにする
- 物語全体の変遷（最初 → 現在）を辿れるようにする
- 保存側は本文の版管理が既にあるため、主に追加するのは表示と
  読み取り経路

## 2. 仕様

### 2.1 取引結果での前後表示

- ギャンブル結果の反映時に、変化前と変化後の本文を **同じ画面に
  セットで** 表示する（ページをまたがない）
- 変わった部分が分かる表示にする（差分の強調。実装方式は
  文字／コマ単位の差分など、既存データで可能な範囲でよい）
- 勝ち・負けの両方で出す。失われた意味・得た表現の既存表示は
  そのまま活かす

### 2.2 変遷ビュー

- 物語ごとに、版の一覧（ラウンド、勝敗、賭けた言葉、報酬、
  版番号）を時系列で表示する
- 各版の本文を表示できる
- **最初と最後（最新）を並べて比べられる** 表示を用意する
- 既存の取引履歴表示と重複する場合は、履歴を拡張する形に寄せ、
  画面を増やしすぎない

### 2.3 データ経路

- 版ごとの本文が API から取得できない場合は、セッション認可の
  範囲で読む読み取り専用エンドポイントを追加する
- 他人のセッションの本文を読める経路は作らない

## 3. 制約

- スマートフォン縦画面が主対象。前後表示は1画面に収まる構成にする
  （本文領域内スクロールは可）
- 書き込み・保存形式は変更しない（表示と読み取りの追加が中心）

## 4. テスト観点

- 取引後に前後表示が出て、変化箇所が強調されること
- 変遷一覧が版の順序どおりに並び、各版の本文が開けること
- 最初と最新の比較表示が動くこと
- 他セッションのデータが読めないこと（エンドポイントを足した場合）
