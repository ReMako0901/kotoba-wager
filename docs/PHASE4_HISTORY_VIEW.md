# Phase 4 仕様： 物語の変遷ビューと変化の前後表示

作成： 2026-11-17（Muse）。ゼミでの指摘（2026-11-13）への対応：
「変わったところを見せる」「最初と最後で比べられる」「ページを
またがずセットに」「変遷を辿れると面白い」。

## 1. 目的

- 取引のたびに本文がどう変わったかを見えるようにする
- 物語全体の変遷（最初 → 現在）を辿れるようにする
- 保存側は本文の版管理が既にあるため、主に追加するのは表示と
  読み取り経路

## 2. 仕様

### 2.1 取引結果での前後表示

- ギャンブル結果の反映時に、変化前と変化後の本文を **同じ画面に
  セットで** 表示する（ページをまたがない）
- 変わった部分が分かる表示にする（差分の強調。実装方式は
  文字／コマ単位の差分など、既存データで可能な範囲でよい）
- 勝ち・負けの両方で出す。失われた意味・得た表現の既存表示は
  そのまま活かす

### 2.2 変遷ビュー

- 物語ごとに、版の一覧（ラウンド、勝敗、賭けた言葉、報酬、
  版番号）を時系列で表示する
- 各版の本文を表示できる
- **最初と最後（最新）を並べて比べられる** 表示を用意する
- 既存の取引履歴表示と重複する場合は、履歴を拡張する形に寄せ、
  画面を増やしすぎない

### 2.3 データ経路

- 版ごとの本文が API から取得できない場合は、セッション認可の
  範囲で読む読み取り専用エンドポイントを追加する
- 他人のセッションの本文を読める経路は作らない

## 3. 制約

- スマートフォン縦画面が主対象。前後表示は1画面に収まる構成にする
  （本文領域内スクロールは可）
- 書き込み・保存形式は変更しない（表示と読み取りの追加が中心）

## 4. テスト観点

- 取引後に前後表示が出て、変化箇所が強調されること
- 変遷一覧が版の順序どおりに並び、各版の本文が開けること
- 最初と最新の比較表示が動くこと
- 他セッションのデータが読めないこと（エンドポイントを足した場合）

## 5. 改訂：原稿用紙をめくる UI へ（2026-11-17、ユーザー指示）

公開版をユーザーがプレイしての改訂指示。**状態：指示済み・未実装。**

- **廃止**：勝敗後に変更前／変更後を横書きで並べる表示（結果画面の
  前後比較と、変遷ビュー内の比較表示）。ゲーム画面の文法から外れる
  ため使わない
- **方針**：ゲーム画面は終始、原稿用紙のままにする。ラウンドが
  進むにつれて原稿用紙が1枚ずつ重なっていき、最新の原稿が一番上に
  来る
- 履歴の見せ方は「紙の束をめくる」形にする。原稿用紙を1枚めくると
  その前の原稿が残っていて、そのまま読める。めくる動きは
  アニメーションで表現する
- 結果の提示も原稿用紙の上で行う（書き換わった新しい原稿が上に
  重なる）。版データの持ち方自体は変えない

## 6. めくり方の具体化とマス目の固定（2026-11-17、ユーザー指示）

§5 の実装をユーザーが触っての追加指示。**状態：実装する。**

- **めくりは「角をつまんで斜めにスワイプ」**：原稿用紙の角を
  つまんで斜め方向へスワイプすると、一番上の原稿がめくれて下の
  原稿が見える、という操作にする。前／次ボタンで切り替える形は
  ユーザーの想定ではない。指（ポインタ）の動きに紙が追従し、
  離した位置でめくり切るか戻るかが決まる、実物の紙に近い手触りに
  する
- **マス目のサイズは全状態で固定**：言葉の選択中、結果表示、
  原稿の切り替え（第◯版の表示切替を含む）など、状態が変わっても
  原稿用紙のマスの大きさは変えない。切り替え時にマスが伸縮して
  画面がピクピク動くのは気持ち悪い、というのがユーザーの指摘。
  レイアウトはマス目を基準に固定し、内容側がそれに合わせる
