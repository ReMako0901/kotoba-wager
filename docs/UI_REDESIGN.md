# UI再設計：アノマ常駐ステージと説明文の削減

ユーザーの指示（2026-11-18）。遊んだ実感として「UIがごちゃついて
いる」「無駄な文章が多すぎる」。方針は次の3点。

1. **アノマは常時表示**し、彼女と勝負している体裁にする
2. **説明文は極限まで削る**。勝率・変化の大きさ等のメタ要素
   （システム側の情報）は一切表示しない
3. 操作のヒントは**文字ではなくUIとアニメーションで見せる**

Phase A（ステージ）と Phase B（文章削減）に分けて実装する。

## Phase A：アノマ常駐ステージ

### 構成

- 画面上部に `AnomaStage` を常駐させる（帯状）。左に
  ポートレート（正方形タイル約88px、顔寄りの切り抜き）、
  右に打ち消し線入りの名前「アノマ」と台詞
- 全画面（タイトル／オープニング／物語選択／ゲーム／
  エンディング）で同じ位置・同じ大きさ。`position: sticky` で
  上部に留まり、下の内容だけがスクロールする
- 表情のクロスフェード（Phase 2 の仕組み）をステージ内の
  ポートレートに移す。常駐するので画面遷移をまたぐ溶け方が
  そのまま活きる
- ステージには `data-expression` 属性を持たせる（Phase 3 の
  瞳文字の接続点にする）

### 台詞と表情の供給

- ステージの内容は「発行者」が決める仕組みにする：
  `StagePublisher`（何も描画せず、内容をステージへ渡し、
  画面を離れるときに既定へ戻す）を Anoma.tsx に用意し、
  各画面が自分の台詞・表情を発行する
- 供給の割り当て
  - タイトル／物語選択／言葉選び／生成中：表情 normal、台詞なし
  - オープニング：現在の台詞（タップ送りは従来どおり）、normal
  - ギャンブル中：台詞なし、表情 taunt（対戦相手として見ている）
  - 結果（通常）：既存の反応判定から台詞と表情（AnomaResult の
    決定的な選択ロジックは純粋関数として切り出して再利用）
  - 到達の提示：台詞群＋surprise。延長戦の入口：台詞群＋taunt。
    延長戦の結果：台詞群＋差分による表情（expressionForEnding）
  - ノーマルエンディング：台詞群＋差分による表情
- 台詞が複数行ある場面（到達・エンディング）は、吹き出し内に
  まとめて表示する

### 置き換え

- Opening／StoryDecision／NormalEnding／結果画面に埋め込まれた
  AnomaFrame は廃止し、ステージに一本化する（ごちゃつきの主因）
- AnomaFrame コンポーネント自体も削除する

## Phase B：説明文の削減と対戦の体裁

### 消すもの（表示から除去。内部の計算・保存は変えない）

- 勝率の表示（ギャンブル選択肢）※内部の確率自体は不変
- 「変化の形」ラベル一式（gamblePresentation の changeShapes）
- ギャンブル選択肢の説明文（option.description と
  サイコロの「4〜6で勝ち。」）
- 報酬モーダルの導入文、報酬の family 表示（表現系/展開系）と
  description
- ギャンブルモーダルの導入文と「このギャンブルで賭ける」等の
  ラベル行（名前だけにする。実行中のスピナーは残す）
- 「赤線の言葉をタップして賭ける。」
- ギャンブル画面冒頭の「賭けた言葉：…／報酬：…」（wager-context）
- 「物語の準備ができた。」「物語も準備中…」等の状態文
  （Status コンポーネントごと廃止）
- 結果確定ボタンの状態込みラベル → 常に「この結果を物語へ」。
  準備中はスピナーと無効状態で示す
- 「報酬は得られず、賭けた言葉の意味が消えます。」
- 「REGは大きく、BIGはさらに大きく物語が変わる当たりです。」
- バカラの「裏向きのカードを選ぶ。」、カード当ての状態文
  （「表のカードを覚えてね。」等）、サイコロの「4〜6で勝ち。」、
  ジャンケンの「あいこは同じ言葉と報酬で再戦します。」
- 章見出しの状態語（「結果」「準備中」）※「第N章」は残す
- 解析中の文（「ことばを仕分け中…」等）→ スピナーだけにする
- 取引ドックの「あとX個選ぼう」等の不足文と、選んだ言葉の
  プレビュー行（数と状態はUIで示す）
- タイトルの「進行は残っています…」文、物語選択の
  「候補を一巡！…」通知文
- 自作入力モーダルの「導入は賭けや書き換えの対象になりません。」
  と「あとX文字入力してください。」（文字数表示と上限エラーは残す）
- 到達画面の見出し（「規定回数に到達しました」「延長戦」）。
  集計の数字とアノマの台詞が担う
- 原稿の束の上の操作説明（「右下を左上へ：前の版…」）と、
  各版キャプションの「賭けた言葉：…／報酬：…」
- 履歴モーダルの「反映待ちの取引は…」文

### 残すもの

アノマの台詞、ボタン名、ギャンブルの名前、集計の数字、
物語の本文と導入、版キャプションの「第Nラウンド・勝利/敗北」、
勝敗の見出し、エラーメッセージ、タイトルの「遊び方」
（ボタンで開く任意表示）、自作入力のラベルと文字数。

### 対戦の体裁

- ブラックジャックの「ディーラー」→「アノマ」
- ジャンケンの「相手」→「アノマ」
- バカラのバンカー/プレイヤーは競技用語としてそのまま

### 原稿をめくるヒントはアニメーションで

- 紙の角（既存の paper-corner）に矢印を出す：右下の角に「↖」、
  左上の角に「↘」。対応する方向の版が存在するときだけ表示
- 矢印は斜めに少しだけ動き続ける（控えめな keyframes、
  約1.6秒周期）。prefers-reduced-motion では静止
- aria-label（ドラッグ操作の説明）は読み上げ用に残す

## 不変条件

確率・強さ・抽選・保存・台詞データ・API契約は変更しない。
ギャンブルの手動操作（自動進行なし）も維持する。
