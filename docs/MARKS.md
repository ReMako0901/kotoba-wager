# 「印」機能（2026-11-27）

賭ける前に、本人が「失いたくない言葉」を示す仕組み。研究目的
（価値の違うものを賭けるときの行動をプレイの記録から見る）ための
事前申告を、アンケートではなく「原稿に印をつける行為」として実装する。
勝敗の確率、賭けのルール、必要数（1／2／3個）は変更しない。

## 1. 印つけ（物語の開始時）

- 物語の開始時、本文の確認の場面で、本文の「意味のまとまり（コマ）」
  単位で最大3つまで印を付けられる。任意で、0個のまま進めることも
  できる（スキップ可能を明示するボタン文言にしなくてよい。
  「これで始める」がそのまま進める）。
- 置き場所:
  - 生成文: 既存の確認・編集画面（「これでいいかしら？」）に
    印つけを同居させる。編集と印つけが同じ画面で完結する。
  - 自作文: セッション開始直後、第1ラウンドの報酬選択の前に、
    本文（原稿）を表示して印つけできる画面を挟む。
  - プリセット: 同じく開始直後に同じ画面を挟む。導線の強さは
    他の開始方法と同じ（特別扱いしない）。
- 提示はアノマの台詞で行う。台詞は次の文をそのまま使う:
  「それでも、本当に変えられたくない記憶には印をつけておくんだよ。
  もっとも、それを賭けるのが楽しいんだけどね」
- 印を付けたコマは原稿上で視覚的に分かるようにする（赤い印。
  既存デザイン系統＝原稿用紙・白黒基調・差し色は赤のみ、に沿った
  控えめな表現）。
- 印は、その物語（章）が始まった後は変更できない。新しい物語では
  付け直せる。

## 2. 賭け選択での扱い

- 印付きのコマも賭け対象として選択可能のままにする（禁止しない）。
- 印付きのコマを選んだ場合のみ、アノマの一言確認を挟む
  （例: 「それ、本当に賭けるの？」程度の一言＋
  「このまま賭ける／選び直す」の二択）。選び直すと選択が解除される。
- 印なしコマだけの選択では確認を挟まない。

## 3. 印の保護（書き換えで変わらない）

- 印付きの表現は、他の言葉を賭けた書き換えでは一切変更しない。
  生成プロンプトに「印付きの表現は一字一句そのまま残す」制約として
  渡し、レビュー段階でも印付き表現が原文どおり残っていることを
  検査する（変わっていたら欠陥として扱う。フォールバック文でも
  印付き表現は保持されること）。
- 例外は、その印付きコマ自体を賭けて負けた場合のみ: そのときは
  通常どおり文脈から消失する。賭けて勝った場合は印付き表現は
  そのまま残る。

## 4. 記録

- セッションに印を付けたコマ（単位の識別子）を保存する。
- ラウンドごとに「印付きを賭けたか／印付きは賭けずに守ったか」と
  勝敗を、既存のプレイ履歴（勝敗記録）・保存の仕組みに合わせて
  記録する。保存形式は既存の Firestore／セッション形式に倣う。

## 進め方

- 作業メモ docs/WORKLOG_MARKS.md を随時更新する。
- コミットしない。CHANGELOG / STATUS / CURRENT_INSTRUCTIONS は触らない。
- 既存の不変条件（AGENTS.md）は全て維持する。
- 既存テストを通し、印まわりのテスト（印の保存、印付き選択の確認、
  保護対象が書き換え結果に原文どおり残ること）を追加する。
