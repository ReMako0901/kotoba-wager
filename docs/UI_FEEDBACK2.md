# 実プレイ後の調整2：表情の拡充と抑制、画面の詰め方

ユーザーの実プレイフィードバック（2026-11-18、スクショ3枚）。

## 1. 異常顔は多用しない

結果画面の「異常」（ uncanny ）が怖すぎるため、出す頻度を
大きく下げる。

- 大きな改変（change）のうち、特に激しい場合だけ uncanny に
  する：強さ8以上、または喪失3個以上
- それ以外の change は通常の表情プール（微笑み系）にする

## 2. 表情のバリエーションを増やす

新規7種を追加する（素材は Muse が用意）：
wink（ウインク）／giggle（含み笑い）／satisfied（満足）／
exasperated（呆れ）／worried（心配）／deadpan（真顔）／
composed（余裕）。閉眼版（*-closed.webp）も同じ命名で用意する。

場面ごとに1つでなくプールから選ぶ形にし、同じ場面でも
表情に幅を持たせる。選択は決定的にする（取引ID等から決め、
再描画で変わらない。台詞選択と同じ考え方）。

- gain → smile / wink / satisfied
- winStreak → laugh / giggle
- loss → taunt / composed
- lossStreak → perplexed / worried / exasperated
- change（激しくない）→ smile / giggle
- change（激しい）→ uncanny（固定）
- 到達 → surprise（固定）
- 延長戦の入口 → taunt / composed
- エンディング：差分が正 → smile / satisfied、
  0 → deadpan、負 → displeased / worried

## 3. 言葉選び画面は原稿用紙を最初から見せる

- 物語の導入文（session.intro の段落）をゲーム画面から消す
  （データと生成への利用はそのまま。表示だけ消す）
- 章とタイトルの見出し行は1行に詰めて、原稿用紙が初見で
  画面に入るようにする。なるべくスクロールさせない

## 4. 選び終えたらギャンブル選択が自動で開く

- 必要な個数を選び終えた瞬間に、ギャンブル選択モーダルを
  自動で開く（下のボタンまでスクロールさせない）
- プレイヤーが閉じた場合は、選択が変わって再び揃うまで
  自動では開かない。下の「ギャンブルを選ぶ」ボタンは
  再度開くために残す

## 5. 報酬モーダルに軽い説明文を戻す

- 報酬の選択肢に、その報酬の短い説明（description）を
  再び表示する（簡略化しすぎたため）
- モーダルの導入段落と family ラベル（表現系/展開系）は
  戻さない

## 含まないもの

確率・強さ・抽選・保存・台詞データの変更、バックエンドの
変更、瞳文字（Phase 3 はユーザーの判断で中止が決まった）。
