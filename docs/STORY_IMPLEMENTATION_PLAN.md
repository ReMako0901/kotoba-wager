# ストーリー実装計画（2026-11-18 作成）

正本は [STORY_DESIGN.md](STORY_DESIGN.md)（『言葉の魔女 アノマ』
ストーリー・世界観実装仕様書 Version 1.0）。この計画は既存実装の
調査結果と、矛盾・重複の整理、フェーズ分けをまとめたもの。
**この計画の作成時点では実装を開始しない。** 各フェーズは
ユーザーの指示で、既存のワークフロー（仕様→Codex 実装→
Muse 検証→コミット）に従って進める。

## 中心テーマ（全フェーズ厳守）

**アノマは言葉の数しか評価しない。人間にとって言葉の価値は
一つずつ異なる。**

- アノマの台詞・評価・集計は、常に「個数」（獲得数・喪失数・
差分）だけで行う。大切な言葉を失っても、アノマは数しか見ない
- 主観的価値はプレイヤー側にある。どの言葉を賭けるかを選ぶ
こと自体が、その表現になる（既存の入口制限＝重い言葉を賭ける
設計と一致する）
- エンディング判定に AI 採点や文章の質の評価を入れない
（SHARED_NOTES の既存方針とも一致）

## 既存実装の調査結果

既にあるもの（再実装しない）：

- 6種のギャンブル（じゃんけん／カード当て／一発サイコロ／
スロット／ブラックジャック／バカラ）と勝敗判定、強さ
- 物語の選択（プリセット約100種＋導入文）と自由入力（20〜100字）
- 言葉の獲得（報酬）・喪失（意味の消去）・改変（書き換え）の
仕組み一式と、版を重ねる原稿 UI
- セッション記録：取引履歴（賭けた言葉・勝敗・報酬・前後の文）、
失われた概念の一覧、版数。仕様 §8 の記録項目の大半はここから
導出できる
- 初心者モード（別の3種の簡易ギャンブル）

無いもの（これから作る）：

- 終了回数（規定回数）とエンディング。GAME_OVERVIEW に
「現在は終了回数・エンディングを実装しておらず、繰り返し
取引するプロトタイプ」と明記されている
- アノマのキャラクター表示・台詞の仕組みそのもの
- オープニングシナリオ
- 脱出／継続の選択と、その記録（到達時点のスナップショット、
延長戦回数、選択履歴はセッションに無い）

## 矛盾・重複の整理

1. **旧メモとの関係**：SHARED_NOTES には「魔女・誘拐・脱出の
物語は将来の世界観案」とあり、反応は「どんな変化にも好意的」
とされていた。STORY_DESIGN が正式資料になったため、今後は
こちらが正。「好意的」ではなく「数しか見ない」がアノマの
反応の原則になる。SHARED_NOTES と GAME_OVERVIEW の該当記述は
フェーズ S1 の着手時に STORY_DESIGN への参照へ更新する
2. **「進行」という言葉の重複**：Phase 4 の「進行」は物語本文が
展開系報酬で前に進むこと（物語内進行）。本仕様の「進行」は
規定回数→脱出権→延長戦というゲーム全体の構造（ストーリー
進行）。別物として扱い、混同しない
3. **ギャンブルの数え方**：仕様 §4 の6種は上級側の6種と一致。
初心者モードの3種（コイントス等）は仕様に記載がない。
アノマの台詞とストーリー進行は、まず上級（本編）を対象に
設計し、初心者モードへの適用は判断待ちとする（下記）
4. **記録データ §8**：大半は既存セッションから導出可能。
新規に必要なのは「規定回数到達時点の状態」「延長戦回数」
「脱出・継続の選択」の3点のみ。バックエンドのセッションに
最小限の追加で済ませる
5. **エンディング B／C／D**：仕様でと明記されて
いる。具体的な条件・内容は未確定であり、勝手に完成させ
ない。フェーズでは分岐の「枠」だけを用意し、内容は
ユーザーの確定を待つ

## 未確定事項（ユーザーの判断待ち）

- **規定回数の数値**：仕様に数値の記載なし。設定データとして
外に出し、数値はユーザーが決める（フェーズ S2 の着手前に
必要）
- **初心者モードへの適用**：アノマの登場とストーリー進行を
初心者モードにも入れるか、本編のみか
- エンディング B／C／D の条件と内容（構想段階のまま保持）
- アノマのキャラクター設定表（ユーザーが次に渡す予定。
見た目・表情・瞳文字の実装はそれを受けてから）

## フェーズ分け

### S1. 台詞基盤とオープニング

- 台詞・シナリオを専用データ（シナリオデータファイル）で管理
する仕組み。ソースコードへの台詞の直書きをしない
- アノマの表示枠（名前＋台詞の提示領域）。キャラクター画像が
無くても成立する形にし、画像は後から差し込める構造にする
- オープニングシナリオ（仕様 §3 の確定文）を、ゲーム開始前に
表示する
- 勝敗・獲得・喪失・改変に対するアノマの基本反応（仕様 §4）。
同じ反応が連続しにくいよう複数候補から選ぶ
- SHARED_NOTES／GAME_OVERVIEW の旧記述を STORY_DESIGN 参照へ
更新

### S2. 規定回数と脱出／継続の選択

- 規定回数を設定データで管理（数値は未確定事項の決定に従う）
- 到達時にアノマが獲得数・喪失数・差分を集計して提示し、
「脱出する／さらに賭ける」の選択肢を出す
- セッションに記録を追加：到達時点のスナップショット、
延長戦回数、脱出・継続の選択
- 既存の「タイトルへ戻る／つづきから」と矛盾しない形にする

### S3. ノーマルエンディング

- 脱出を選択したときのエンディング表示。集計は個数のみ
- 台詞分岐は3つ：言葉が増えた／減った／増減ゼロ。仕様 §6-A の
確定台詞を用い、アノマが数字だけで評価するズレを会話で
表現する（説明台詞にしない）
- エンディング到達後の扱い（タイトルへ戻る、記録の残し方）は
既存のセッション終了の流れに合わせる

### S4. 延長戦

- 延長戦専用のアノマ台詞（仕様 §5 の確定台詞を含む）
- 延長戦の累計回数を、追加台詞の発生条件に使える形にする

### S5. 追加エンディングの枠のみ（内容は実装しない）

- バッド／グッド／トゥルーの分岐を、条件を設定データで差し
替え可能な構造としてだけ用意する
- 条件・台詞・演出は未確定のまま。プレースホルダで進行が
止まらないこと（通常はノーマルエンディングに落ちる）

### S6. キャラクター統合（設定表とアート待ち）

- アノマの立ち絵・少しのアニメーションの組み込み
- 瞳の漢字の状態連動（仕様 §7 の表：通常「言」、獲得「得・増・
生・添」、喪失「失・欠・亡・消」、大きな改変「歪・変・無」、
継続「続・賭」、脱出「帰・終」。重大時は両目＋グリッチ）
- 名札（「アノマ」に取り消し線）の表現
- キャラクター設定表を受け取ってから仕様を切る。この計画では
枠組みだけを示す
