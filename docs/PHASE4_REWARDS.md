# Phase 4 仕様： 報酬の多様化と物語の進展性

作成： 2026-11-17（Muse）。決定の経緯は `PROJECT_PLAN.md` の Phase 4。
進展性は勝利時の報酬として実装し、報酬の多様化と一体で設計する
（2026-11-13 ユーザー決定）。

## 1. 目的

- 現行の報酬は「要求数（1/2/3個）× 段階（序盤/中盤/後半）」の3×3で
  9種固定。同段階では同じ報酬が繰り返し出て単調
- 進展性の定義（ユーザー）： 新しい要素が追加されて物語の展開が進むこと。
  現状は人物が増える・修飾が変わるだけで、負け続けると停滞する

## 2. 仕様

### 2.1 枠組みは維持

- 報酬を選ぶ → 要求数ちょうど言葉を賭ける → ギャンブル、の流れは不変
- コマはどれも同価な1個。点数制・AI採点は入れない

### 2.2 報酬を2系統に分ける

- **表現系**： 既存要素の描写を深める。新しい要素は足さない
- **展開系**： 新しい要素を1つ追加し、物語を前へ進める（進展性は
  この系統が担う）

### 2.3 候補プール化

- 3×3の各セルに、系統別の候補プールを持たせる。現行の9種は
  プールの構成員として残す
- 追加候補（叩き台として確定扱い。名称は暫定でよい）：
  - 展開系： 次の場面へ（時間の経過）、新しい場所、誰かの約束・目的、
    関係の変化、小さな危機の接近
  - 表現系： 鮮やかな比喩、心の声
- セルへの割り当ては、要求数と段階が大きいほど展開の規模が大きく
  なるよう自然に配分する

### 2.4 提示の仕方

- 3択の提示には **展開系を最低1つ含める**（進展の機会を毎回保証する）
- 各選択肢に系統（表現／展開）が分かる表示を付ける。プレイヤーが
  「どう作りたいか」で選べることが主体感（ゼミ指摘）への応答になる
- 提示された3択はラウンドの状態として保存し、再試行や再読み込みで
  変わらない（抽選を一度だけ確定する既存原則と同じ）

### 2.5 生成側の編集方針

- 展開系の報酬では、編集プロンプトに「新しい要素を1つ追加し、
  物語を前へ進める」を明示する。強さによる編集規模の調整は既存どおり
- 表現系の報酬では「新しい要素を足さず、既存要素の描写を深める」を
  明示する

### 2.6 負け続け対策

- 進展は勝利報酬に紐づける（決定済み）。負けても喪失の意味は
  薄めない。今回の範囲では、負け側への進展付与は入れない

## 3. テスト観点

- 各セルのプールに系統別の候補が存在すること
- 提示3択に展開系が最低1つ含まれること
- 提示が保存され、再試行で変わらないこと
- 展開系／表現系で編集プロンプトの方針が切り替わること
- 既存の報酬フロー（要求数ちょうど、成立する報酬だけ表示）が
  壊れていないこと
