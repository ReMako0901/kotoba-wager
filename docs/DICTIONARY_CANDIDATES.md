# 既存の無償辞書データを使う案

調査：2026-11-11。ユーザーの意図は、小規模な手作業の例外辞書ではなく、既存の無償辞書を取り込んで参照させること。前回作成したゲーム用JSONは小さな補正層であり、この要望そのものを実装済みとは扱わない。

## 現在確認できたこと

現在すでにSudachiPy＋sudachidict-coreという一般辞書を使用している。補正前の実行結果を確認したところ、SplitMode A/Cとも「拍子抜け」は「拍子／抜け」に分かれた。辞書に語がないことまでは確認していない。解析結果の分割と、辞書内の収録有無は別である。

## 候補

|データ|用途と今回の適合性|確認範囲|
|---|---|---|
|Wiktionary日本語版の機械可読データ（Kaikki/Wiktextract）|見出し・品詞・意味等を利用し、慣用表現をまとめる候補を抽出する。第一の評価候補|日本語データ配布ページ、品詞別一覧、ライセンス案内、Wiktionaryの「拍子抜け」本文を確認|
|JMdict|語・表現・品詞等の構造化辞書。expression、idiomatic expression等のタグを候補抽出に利用できる|公式の品詞コード説明・ライセンス本文を確認。本件の対象語の収録・分割改善は未検証|
|SudachiDict Full|現行Coreから差し替えやすい比較候補だが、公式説明では固有名詞を多く含む拡張|公式READMEを確認。Fullのダウンロード・比較実測はしていない|

Wiktionaryには「拍子抜け」が名詞およびサ変動詞として載っている。この見出しを使って分断を防ぐ設計は可能。ただし全体精度が上がるかは未実証。JMdictやWiktionaryにある語をすべて最長一致で結合すると、文全体に近い表現までまとめる恐れがある。見出し種別・長さ・形態素境界・活用を検査する必要がある。

## 想定する実装（未実装）

1. 辞書のスナップショットを取得し、出所・版・ライセンス・ハッシュを記録する。
2. 日本語の見出し・品詞・必要なら意味を抽出して、ローカル検索できる形式に変換する。
3. Sudachiで分割した候補を辞書と照合し、登録された一まとまりの表現を保護する。
4. 助詞等のつなぎ、活用、ゲームとしての選択可否を別に判定する。
5. 元のコマ列と改善後を実プレイの正解例で比較し、誤結合・未検出・誤選択・時間・メモリを確認する。

全辞書を毎回Geminiへ送信する必要はない。プログラムで辞書を照合する方式なら、追加のモデル呼出は不要。意味の説明をGeminiにも参照させる場合は、本文に該当する項目だけを渡す方式を検討する。

「代わりに」のような表現を賭けられなくするかは、辞書の収録・品詞だけでは確定しない。語として存在することと、本ゲームで選択させたいことは別。現行のユーザー指定の非選択ルールは残せる。

## 配布データ・利用条件

Kaikkiの日本語ページにはJSONL配布があるが、従来のpostprocessedデータは非推奨でrawデータの利用が案内されている。採用時は最新のraw配布先とスキーマを確認する。Wiktionary由来データのライセンス条件と出典を保持する。

JMdictの公式ライセンスページはCC BY-SA 4.0およびクレジット・ドキュメント・更新等の案内を掲載している。採用時に同梱物と更新方法を確認する。無償であっても無条件のパブリックドメインとは扱わない。

今回、新しい辞書ファイルの大量ダウンロード、パッケージ追加、インポート処理、ゲームコードの変更、Render再配信は実施していない。候補の調査と実装方針の整理のみ。
