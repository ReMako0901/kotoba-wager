# Phase 4 仕様： ギャンブル演出・UI の品質向上

作成： 2026-11-17（Muse）。Phase 4「ギャンブル部分のクオリティ
アップ」「UI のアニメーション追加」「UI 全体のクオリティアップ」と、
ゼミ指摘「ギャンブルの意義が薄い」への演出面の対応。

## 1. 目的

- ギャンブルを「結果だけが返る抽選」に見せない。臨む過程の
  ドキドキ（ニアミスで熱が入る心理的揺さぶり＝仮説「着火」）を
  演出で支える
- 生成待ちの時間も含め、プレイ全体の手触りを上げる

## 2. 仕様

### 2.1 ギャンブル選択画面

- 各ギャンブルに「変化の形」の性質表示を添える（例： 一か八か、
  手堅い、波がある、など。数値の裏にある個性を言葉で見せる）
- **勝率などの数値表示は現状維持**（表示を消すかは未確定事項。
  今回は触らない）
- **ギャンブルの名称は変更しない**（未確定事項。今回は触らない）

### 2.2 ギャンブル中の演出

- 結果が出るまでの間に、結果を予感させる段階的な演出を入れる
  （スロットの絵柄が止まっていく、サイコロが転がる、カードが
  めくれる等、種類ごとの見せ方）
- ニアミス（あと少しで当たる形）は、実際の結果がそうなった
  ときに **見せ方として強調してよい**。ただし確率・結果・強さは
  一切変えない（演出は結果の解釈であり、抽選への介入ではない）
- 演出はスキップ可能にし、長くても数秒に収める

### 2.3 結果から本文への接続

- 結果表示から本文の書き換わりへ、アニメーションでつなぐ
  （敗北時は墨が粉になる既存モチーフの演出を磨く。粉の蓄積は
  ラウンドをまたいで残る現行仕様を維持）
- 生成中は待ち時間と分かる表示を出す（無言の固まりに見せない）

### 2.4 UI 全体

- 余白・文字サイズ・タップ領域の統一感を見直す
- 報酬選択・言葉選択・結果表示に小さなアニメーションを足す
- 純白・明朝・赤線の既存デザイン文法は維持する

## 2.5 制作の進め方（ツール運用、2026-11-17 追記）

- 実装前にデザイン方針（配色・タイポグラフィ・余白のルール）を
  簡潔に決めてから着手する。UI UX Pro Max のデザインシステム面の
  指針は参考にしてよいが、Tailwind / shadcn 前提の部品流儀は
  このゲームの文法（純白・明朝・赤線、既存 CSS）に合わないため
  持ち込まない
- 実装後は Chrome DevTools MCP で実際にページを開き、スマート
  フォン表示でスクリーンショットを撮って表示崩れを確認し、
  問題がなくなるまで直す（作りっぱなしにしない）
- 仕上げの批評（余白・文字・メリハリ）は Impeccable が使える
  環境なら使う。使えない場合はこの確認を省略せず、スクリーン
  ショットでの目視確認に置き換える

## 2.6 動きの指定（2026-11-17、ユーザーが渡した動き30一覧から選定）

色は使わず、名前のある動きで指定する。いずれも白・黒・赤の
文法の中で行う。

- Motion: skeleton screen + shimmer effect.
  きっかけ：生成（書き換え）の待ち時間。動く物：本文エリアに
  原稿マスの骨格を表示し、上を薄い光が流れる。長さ：生成完了
  まで継続。終わった後：本文へふわっと切り替わる。
- Motion: stagger animation.
  きっかけ：報酬の3択が出る時。動く物：3枚の選択肢が60msずつ
  ずれて下から現れる。長さ：0.25秒ほど、すっと止まる。
- Motion: spring animation.
  きっかけ：ギャンブルの結果が出る時。動く物：結果のパネルが
  弾むように現れる。長さ：0.4秒ほど、ばねの勢い。ニアミス
  演出では結果の直前に pulse animation で一拍置く。
- Motion: circular reveal.
  きっかけ：ラウンドの切り替わり。動く物：墨の円が広がる
  ように画面が切り替わる。長さ：0.35秒ほど。
- Motion: loading button.
  きっかけ：「賭ける」を押した後。動く物：ボタンの中で
  スピナーが回り、二重押しできない状態になる。生成完了で
  元に戻る。
- 端末の「視差効果を減らす」等がオンの時は、上記の動きを
  フェードのみに落とす（prefers-reduced-motion 対応）。

## 3. 制約（重要）

- 確率、強さ、抽選、保存の仕様は一切変更しない
- 演出のためにバックエンドの結果を遅らせたり変えたりしない
- スマートフォン縦画面で重くならないこと（アニメーションは
  CSS 中心、過剰なライブラリ追加はしない）

## 4. テスト観点

- 全ギャンブル種別で演出が最後まで再生され、結果表示に着地すること
- スキップが効くこと
- 演出の有無で勝敗・強さ・本文の結果が変わらないこと
- フロントエンドのビルドが通ること
