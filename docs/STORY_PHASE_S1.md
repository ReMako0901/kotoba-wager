# ストーリー実装フェーズ S1：台詞基盤とオープニング

正本は [STORY_DESIGN.md](STORY_DESIGN.md) と
[STORY_IMPLEMENTATION_PLAN.md](STORY_IMPLEMENTATION_PLAN.md)。
中心テーマ厳守：アノマの台詞と評価は常に言葉の「個数」だけに
基づく。大切な言葉を失っても、アノマは数しか見ない。

## 1. シナリオデータ

- 台詞は専用のシナリオデータ（フロントエンドのデータモジュール）
  で管理する。コンポーネントへの台詞の直書きをしない
- データ構造は「場面（トリガー）→ 台詞候補の配列」。候補が
  複数ある場面では、直前と同じ台詞が連続しないように選ぶ
- S1 の台詞は STORY_DESIGN §3（オープニング）と §4（基本反応）
  の確定文だけを使う。新しい台詞を創作しない。候補の追加は
  データ側だけで完結する形にする

## 2. アノマの表示枠

- 名前「アノマ」と台詞を表示する枠を設ける。体裁は既存の文法
  （純白・明朝・白黒＋赤）に従う
- 名前表示には名札のモチーフを使う：「アノマ」の文字の中央を
  細い一本線で取り消す（判読可能に保つ。ANOMA_CHARACTER §4）
- キャラクター画像はまだ無い。画像が無くても成立する枠にし、
  後から画像を差し込める構造にする（S6 で統合）
- 瞳の漢字は画像側の演出なので S1 では描かない。ただし現在の
  反応種別（通常／獲得／喪失／改変など）を、S6 が参照できる
  状態として保持する

## 3. オープニング

- 新規ゲーム開始時（タイトルの「はじめる」から物語選択へ
  進む前）に、STORY_DESIGN §3 のオープニングを表示する
- 台詞はタップ／クリックで1つずつ送る（自動で進めない。
  ギャンブルの自動進行禁止と同じ原則）。スキップも可能にする
- 「つづきから」の再開時は表示しない
- 初心者モード・上級モードのどちらでも表示する（物語の層は
  両モード共通、2026-11-18 決定）

## 4. 基本反応

- 各ラウンドの結果が確定した画面で、アノマの反応を1つ表示する
- トリガーの対応：
  - 勝利 → 獲得の台詞
  - 敗北 → 喪失の台詞
  - 2連勝以上 → 複数回勝利の台詞を優先
  - 2連敗以上 → 複数回敗北の台詞を優先
  - 大きな改変（そのラウンドで失われた概念が2つ以上、または
    ギャンブルの強さが6以上）→ 改変の台詞を優先
- 優先順位は「大きな改変 ＞ 連続勝敗 ＞ 単発の勝敗」とする
- 初心者モード（BeginnerPlay）と上級（GamblePlay）の両方の
  結果表示に枠を出す

## 5. 旧資料の整理

- SHARED_NOTES と GAME_OVERVIEW の「魔女・脱出は将来案」
  「エンディング未実装」等の記述を、STORY_DESIGN を正とする
  形に更新する（将来案ではなく正式設計になったこと、反応の
  原則は「数しか見ない」であること）

## テスト観点

- シナリオデータに全トリガーの台詞が存在し、オープニングの
  台詞が STORY_DESIGN §3 と一致すること
- 台詞選択で同じ台詞が連続しないこと
- 新規開始でオープニングが出て、再開では出ないこと
- 勝敗・連勝連敗・大きな改変で対応する反応が選ばれること
- 両モードの結果表示にアノマの枠が出ること
