# ストーリー実装フェーズ S2＋S3：規定回数・脱出／継続・ノーマルエンディング

正本は [STORY_DESIGN.md](STORY_DESIGN.md) §5・§6-A・§8 と
[STORY_IMPLEMENTATION_PLAN.md](STORY_IMPLEMENTATION_PLAN.md)。
計画では S2 と S3 に分かれているが、脱出先が行き止まりに
ならないよう一体で実装する。

中心テーマ厳守：集計とアノマの評価は言葉の「個数」だけ。
獲得数・喪失数・差分の数字だけでアノマは語り、大切な言葉を
失ったかどうかは評価に一切入らない。

## 1. 規定回数

- 規定回数はセッションごとに 5〜8 回からランダムに決まる
  （2026-11-18 決定）。範囲はバックエンドの設定値として持ち、
  後から調整できるようにする
- 抽選はサーバー側で1回だけ行い、セッションに保存する。
  再読み込みや再開で変わらない（既存の「抽選は保存し、
  やり直さない」原則に従う）
- 既存セッション（この機能より前に作られたもの）は、次に
  読み込まれた時点で1回だけ抽選して保存する
- プレイヤーには事前に回数を見せない。到達したときに
  アノマが告げる

## 2. 数え方

- 勝負回数＝確定した取引（committed なトランザクション）の数
- 獲得数＝勝利した取引の数（勝つたび報酬の表現が1つ増える）
- 喪失数＝敗北した取引で賭けた言葉の個数の合計
- 差分＝獲得数 − 喪失数
- すべて既存の取引記録から導出できる。新しい集計の仕組みは
  作らず、この定義を集計の正とする

## 3. 到達と選択

- 確定した取引の数が規定回数に達したラウンドの結果画面で、
  アノマが到達を告げ、集計（獲得数・喪失数・差分）を提示し、
  選択肢「脱出する／さらに賭ける」を出す
- 到達の時点で、到達時点の状態（回数・獲得数・喪失数・差分）
  をセッションにスナップショットとして保存する
- 選択はサーバーに記録する（§8 の「脱出・継続の選択」）。
  記録のためのエンドポイントを用意し、フェーズの遷移
  （強制参加→脱出可能→延長戦）をセッションが持つ
- アノマの台詞は STORY_DESIGN §6-A の確定文を使う。到達の
  告知そのものは UI の見出し文で担い、アノマの台詞を
  新たに創作しない

## 4. 延長戦

- 「さらに賭ける」を選ぶと延長戦に入る。以後の確定した
  取引は延長戦回数として数える
- 延長戦に入るとき、アノマが §5 の確定文
  （「帰れるのに、まだ遊ぶの？」等）で迎える
- 延長戦の結果画面でも「脱出する」を選べる状態を保つ
- 延長戦専用台詞の拡充は S4 で行う。ここでは入口だけ作る

## 5. ノーマルエンディング（S3）

- 「脱出する」を選ぶとエンディング画面に移る。表示するのは
  最終集計（総勝負回数・獲得数・喪失数・差分）と、アノマの
  締めの台詞
- 台詞は差分の符号で3分岐し、§6-A の確定文を使う：
  増えた場合／減った場合／増減ゼロの場合
- 延長戦を経て脱出した場合も、エンディングはこのノーマル
  エンディングとし、集計は全体の合計で出す（到達時点の
  スナップショットは記録として別に残る）
- エンディング後はセッションを終了状態にし、「つづきから」の
  対象から外す。エンディング画面からはタイトルへ戻れる

## 6. 両モード・既存機能との整合

- 規定回数と選択は初心者・上級の両モードに適用する
- 既存の「タイトルへ戻る／つづきから」と矛盾させない。
  進行中セッションの再開では、フェーズと集計が復元される

## テスト観点

- 規定回数が 5〜8 の範囲で抽選され、保存されて変わらない
  こと。既存セッションにも1回だけ付与されること
- 到達した取引でスナップショットが保存され、到達前は
  保存されないこと
- 選択の記録とフェーズ遷移（脱出→終了、継続→延長戦）
- 延長戦の回数が数えられ、延長戦からも脱出できること
- エンディングの台詞が差分の符号で正しく分岐すること
- 集計（獲得数・喪失数・差分）が取引記録と一致すること
