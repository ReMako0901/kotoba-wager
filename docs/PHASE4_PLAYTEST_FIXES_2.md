# プレイ確認の指摘 第2弾（2026-11-17、Claude の実プレイ報告より）

ユーザーが全件の修正を指示。フロントエンドのみ（バックエンド・
API 契約・保存形式は変更しない）。ゲーム内の説明文は、後で
ゲームマスターのキャラクターが追加され、そのキャラとの対戦と
いう体裁になる前提がある。説明の作り込みは最小限（短い一文の
補足まで）に留め、チュートリアル的な大規模追加はしない。

## 1. タイトル画面の表示が消える

- 症状：初回は「はじめる」の下に副題「言葉を賭けて、物語を
  書き換える」と「遊び方」「つづきから」があったが、遊んで
  タイトルへ戻った後も再読み込み後も消えたまま戻らない
- あるべき姿：副題と「遊び方」は常時表示。「つづきから」は
  再開できるセッションがあるときだけ表示し、実際に再開できる

## 2. 結果画面の本文はみ出し

- 症状：最新版の最下行が原稿の枠からはみ出して切れる（本文が
  長い場合）。言葉選択画面では逆に本文が上部だけで下半分が空白
- あるべき姿：マスの大きさ（--cell-size）は固定のまま、行数は
  本文量から決まり、全文が枠内に収まる。はみ出しも切れもない

## 3. タイトルへ戻ると進行が消える

- 症状：結果画面の戻る操作が確認なしで即タイトルへ戻り、進行が
  破棄されるように見える。再開の案内もない
- あるべき姿：進行中のセッションがある状態でタイトルへ戻る
  ときは確認を出す（または再開可能な形で残し、その旨を示す）。
  §1 の「つづきから」と合わせて成立させる

## 4. 結果表示のフェード

- 症状：結果画面の遷移直後、文字全体が薄いグレーでかすれ、
  壊れているように見える
- あるべき姿：フェードは読める濃さから始めるか、短くする。
  初見で「読めない」と感じさせない

## 5. 生成待ち画面の統一と進捗

- 症状：待ち画面の構成がラウンドで違う（白紙の原稿が出る回と、
  完了後にプレビューが消える回がある）。進捗の手がかりが小さな
  文字だけで、30〜45秒の待ちが止まっているように見える。完了の
  合図も小さい
- あるべき姿：待ち画面は全ラウンド共通の構成（スケルトンの
  原稿＋状態文）。経過が分かる手がかり（経過秒数や段階を思わせ
  ない範囲の状態文の切り替え）を置く。完了時は結果へのボタンが
  明確に分かる状態変化にする

## 6. 言葉選択の分かりにくさ

- 賭けられる言葉の印が淡すぎて、普通の文字と区別しにくい。
  選んだ状態も淡い。→ 印と選択状態のコントラストを上げる
  （白・黒・赤の文法の中で）
- 画面に操作説明がない → 短い一文を置く（例：赤線の言葉を
  タップして賭ける）
- 1語が列をまたいで2つのボタンに割れる（「花」「の上を」）→
  1ユニットは1つの操作部として扱い、割れて見えないようにする
- 下部バー：押せない「あと1個選ぼう →」が進むボタンに見える →
  無効状態はボタンに見えない見た目にし、文言は案内として置く

## 7. 報酬選択の補足（最小限）

- 「1個／2個／3個」が「賭ける言葉の数」だと選択時点で分かる
  一文を添える
- 報酬の説明に、勝てばどうなる／負ければ報酬は得られず賭けた
  言葉の意味が消える、の要点を短く添える

## 8. ギャンブル選択の補足（最小限）

- 「初心者／上級者」タブの選択がラウンドをまたいで残る →
  ラウンドごとに初期状態（初心者）へ戻す
- 候補のギャンブルがラウンドごとに入れ替わる理由が分かる
  一文を添える（毎回3つが提示される形式であること）
- 勝率表示の表記をそろえる（「33%〜」のような曖昧な書き方を
  やめ、各ギャンブルの表示形式を統一する）

## 9. ギャンブル画面の共通化

- 全ギャンブル画面の上部に、いま賭けている言葉と選んだ報酬を
  常時表示する（じゃんけん画面の空白感の解消も兼ねる）
- じゃんけん：あいこは再戦になることを、対戦前に一文で示す
- ギャンブル中に履歴ボタンが無効になる画面がある → 無効に
  するなら理由が分かる形に、できれば開けるようにそろえる
- 負けた直後、報酬は得られなかったことが分かる一文を、
  書き換えが始まる前に出す
- スロット：STOP を十分な大きさのボタンにする。「演出を
  スキップ」は操作の近くに置く。REG／BIG の違いと効果を
  結果に一文で添える

## 10. 履歴ダイアログ

- 開発者向け情報（モデル名、トークン数、「生成3回」）を
  プレイヤー向け表示から外す。「生成回数」を出すなら
  プレイ回数として数える
- ダイアログで表示中の版と、背後の結果画面の版を同期させる
  （閉じたときに食い違わない）

## 11. 「どこが変わった？」と原稿の対応

- 開いたら最新版の原稿上で、変わった箇所がハイライトで
  確かめられるようにする（現状は文章の要約だけで、原稿上に
  印がないように見える）

## 12. 画面間の統一

- タイトルへ戻る操作の表記を全画面でそろえる（「タイトルへ」
  に統一する等）
- 物語選択の候補入れ替えボタンの表記を、初回と2回目以降で
  変えない。カードの「↗」は、押すと何が起きるか分かる形に
  するか、カード自体で全文（導入と本文）を読んでから始め
  られる形にする
- カスタム入力：開始ボタンが押せない理由（あと何文字か）を
  表示する。文字数カウンタは入力前から表示する。導入欄にも
  上限や目安があれば添える。本文の入力例をプレースホルダに
  添える

## 13. 紙めくりの目印

- めくれる角の印が淡く小さい → 折り返しの陰影を少し強め、
  操作案内の文字も見落とさない大きさにする。初めてめくる
  までは案内を残す形でよい

## テスト観点

- タイトル画面で副題・遊び方が常時表示されること。再開可能な
  セッションがある場合のみ「つづきから」が出て再開できること
- 長い本文でも原稿の行数が足り、はみ出し前提の固定行数指定が
  残っていないこと。--cell-size の単一定義は維持
- タブ初期化、履歴のプレイヤー向け表示（モデル名・トークン数を
  含まない）、版同期、言葉ユニットの単一ボタン化など、今回の
  変更点を既存のテスト基盤で検証できる形にする
