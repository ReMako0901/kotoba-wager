# その他の共有事項・判断の引き継ぎ

## ユーザーの判断を尊重する

- 最初の作品を自作することは必須ではない。現在は保存済み開始文の3択＋リロール。
- 約10,000件の開始文は将来案。現在は100件。開始するたびにAIで新作を生成する仕様にしない。
- 本文は短く、軽く、ポップ。短さは固定秒数・文字数の研究上の必然ではなく体験上の方針。現コードの最大140文字は仮制約。
- 不条理さや奇抜さだけを目的にしない。「傘が海へ行きたいと騒ぐ」は不評。「おそろいの日傘」へ変更済み。一方、既存の月・うさぎ等の空想設定をすべて削除する指示ではない。
- 1語の小さな喪失で人物・場面まで総入替えしない。複数の主要対象を失った場合の大きな変化は許容される。
- 点数ピッタリ方式は自由な選択を妨げたため廃止。同じ重みの個数方式を維持する。
- 全コマ選択可能にも不満があり、一般的な動作・副詞・接続語は枠なしでよい。「持って出た」「なぜか」「代わりに」は枠なし、「拍子抜け」は一まとまりが希望。
- UIは報酬3択を先にポップアップ、次に本文選択、最後に実行。カジノの派手な装飾ではなくモノクロで文章を主役にする。

## 過去案・未決定の案

音楽版、ハムスター案、スロット演出等は研究探索の履歴。現実装へ勝手に混ぜない。

魔女・誘拐・脱出の物語は将来の世界観案。反応はどんな変化にも好意的で、作品の良し悪しをAI採点してエンディングを決める方針ではない。エンディングは勝敗による案だが未実装。現プロトタイプに立ち絵や終了回数はない。

ゼミで「友達と盛り上がる」「物々交換」「小説や画像でも可能」等の意見があった。会話の案であり、対戦・SNS共有・画像生成等が現仕様に決定したわけではない。

GitHubへのゲームソース公開と既存Render無料サービスの利用は承認済み。ローカル研究フォルダー全体を公開する承認ではない。許可済みの通常更新で承認を取り直す必要はないが、新しい課金・権限・公開範囲は別。

PagesはmainへのpushでActions配信。Renderはこれまで手動デプロイを使用。GitHubへのpush成功だけでAPIが更新されたと扱わない。現在ユーザーは公開版をプレイ中で、辞書・引き継ぎ資料の今回更新ではRenderを再起動しない。

無料Renderのローカルファイルは永続でなく、休止・再配信等でセッションや呼出カウンターを失い得る。正確な実験記録・継続セーブには永続保存を別途実装する必要がある。セッションIDを知れば取得できる試作APIで、公開アカウント基盤・認可・厳密な費用制限は未整備。参加者の個人情報を保存する設計は未検討。

## 秘密情報とGit

既存キーはローカル `.env` とRenderの非公開環境変数。値を読んで報告しない。フロントへ渡さず、キーを貼り直すよう依頼しない。`.env.example` は空のサンプルのみ。

追跡しないもの：`.env`、認証情報、`data/runtime`、`artifacts`、`.venv`、node_modules、dist、キャッシュ、プレイ画像。公開専用へ同期する際も同様。

意味のある差分ごとに日本語コミット。ステージ前の状態を確認し、他者の作業や無関係な研究資料を混ぜない。履歴改変・force push禁止。親リポジトリの既存未追跡研究資料は残っていて正常。このゲームの未コミット有無と区別する。

## 根拠・評価

自動テスト成功、実Geminiでの成功、ブラウザ表示確認、公開配信は別の根拠。生成の自然さ・意味の完全消失・不可逆性は保証していない。研究の新規性・有用性・面白さは未実証。過去の試験を今回実行したと書かない。

開発者向け資料は中立な説明文にする。会話のキャラクター口調はゲーム文面や技術ドキュメントに持ち込まない。
