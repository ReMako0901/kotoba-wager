# Codex 指示文： Phase 4 仕様A・B（賭け対象の入口制限＋ストーリーの導入）の実装

（2026-11-13、Muse 作成。仕様Bも同日にユーザー承認で確定したため、
対象は A・B 両方。Codex はこの指示書と仕様書を読んで実装する）

## 対象

リポジトリ `docs/PHASE4_BETTING_SCOPE_AND_INTRO.md` の **2章（仕様A）と
3章（仕様B）** を実装する。順番は A → B とし、コミットも分ける。

## 着手前に読むもの

- `AGENTS.md`（リポジトリの決め事）
- `docs/PHASE4_BETTING_SCOPE_AND_INTRO.md`（本仕様）
- `docs/WORD_DICTIONARY.md`（辞書と区切りの仕様。今回は区切り自体は
  変えず、選択可否のフィルタだけを足す）
- `docs/GAME_OVERVIEW.md`、`docs/STATUS.md`、`docs/TODO.md`

## 仕様A（賭け対象の入口制限）の実装内容

1. 賭け対象を「名詞的な核＋対象を特定する修飾」に限定する追加フィルタを、
   既存の選択可否判定に足す。判定はルール側（形態素ルール＋辞書）で行い、
   AI 判定で選択肢を塞がない
2. 区切りとオフセットは変更しない。「黄色い」「日傘」は別コマのまま、
   両方とも対象になること
3. 程度・様態の副詞、接続表現、形式名詞的な軽いコマ、一般的な動作は
   対象外（現行で対象外のものは維持）
4. 動詞コマは現行の線引き維持で確定（場面を担う動詞は対象、一般的な
   動作は対象外）
5. 開始文100件を再生成し（`scripts/precompute_starter_analysis.py`）、
   全件で賭け対象が3個以上あることを検証して報告する。満たさない文が
   あれば、件数を減らしたり勝手に本文を書き換えたりせず、止めて報告する
6. 自作文は開始時に対象コマ数を数え、3個未満なら開始させない。文面は
   仕様書 2.5 の案を使う
7. プレイ中の枯渇は既存仕様（成立する報酬だけ表示）のまま。新規の
   救済は入れない

## 仕様B（ストーリーの導入）の実装内容

1. 導入部（1〜2文、賭け対象外・書き換え対象外）＋本文の2層構造にする。
   導入は本文の整合のための文脈として生成プロンプトにだけ渡す
2. 開始文100件には、既存の開始文へ導入を書き足す。**導入の下書きは
   一覧ファイル（例： `docs/STARTER_INTROS_DRAFT.md`）に全件分を出し、
   ユーザーの確認が取れるまで開始文データへ取り込まない**
3. 自作文の導入は任意入力（空でも開始可）。対象コマ数の判定は本文
   だけで行う
4. 開始画面では導入を本文の上に続けて表示する

## 守ること

- コマはどれも同価な1個。要求個数1／2／3個の方式は変えない
- 抽選は一度だけ確定・保存。再試行で再抽選しない
- テストは仕様書 2.8 の観点を含める。辞書例外を足す場合は
  `WORD_DICTIONARY.md` の追記手順（実例＋対比例）に従う
- 変更に合わせて `docs/CHANGELOG.md`、`docs/STATUS.md`、`docs/TODO.md`、
  `docs/GAME_OVERVIEW.md`、`docs/WORD_DICTIONARY.md` を更新する
- 意味のある単位で日本語コミット。`git add .` の無差別使用禁止
- **デプロイはしない**。実装・テスト・開始文の検証までで止め、結果を
  報告する。デプロイはユーザーの明示指示後に別途行う
- エラー時は別解を試さず、止めて報告する
