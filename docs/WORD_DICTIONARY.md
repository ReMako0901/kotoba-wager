# ゲーム用辞書の編集方法

## 実現していること

Sudachiの一般辞書で分割し、Wiktionaryの既存データから抽出した見出しと照合して、複合語・慣用句を結合する。あわせてゲーム固有の優先ルールをJSONで管理する。どちらもバックエンドで参照し、追加のAI呼出は発生しない。

- `data/lexicons/wiktionary_ja.json`：Wiktionaryから抽出した13,907語。名詞系12,070、慣用句1,837。410,249バイト。元データは2026-11-01版jawiktionary、Kaikki/Wiktextract配布。
- `data/segmentation_dictionary.json`：ゲーム固有の手動結合・非選択指定。現在の手動結合は1件（「消しゴム」）、非選択は6件。「拍子抜け」は手動登録ではなくWiktionaryの索引から認識する。

## 外部辞書の抽出・照合

抽出条件は、日本語 (`lang_code=ja`)、3〜12文字、漢字を含む日本語表記、名詞系または慣用句のタグ・分類がある句、現行SudachiのSplitMode Cで単独見出しを複数形態素に切るもの。索引に語釈・例文は入れない。

連続する形態素の原文表記が見出しと一致すれば長い一致を優先する。句読点や空白をまたがない。ゲーム側の接続表現・手動結合が優先。例えば「猫の手も借りたい」を一つのコマにする一方、「代金の代わりに」は接続表現を含むので辞書があっても一括で結合しない。

活用形・読み・全角半角・表記ゆれは自動推定しない。タグのない句、ひらがなだけの句、13文字以上、単独では分かれないが文脈次第で分かれる見出し等は対象外になり得る。辞書にあることだけで文脈上の意味は確定しない。

再生成（`story-wager/`で実行。利用する版のデータ・ハッシュを確認する）：

```sh
.venv/bin/python scripts/import_wiktionary.py artifacts/dictionary-source/jawiktionary.jsonl.gz data/lexicons/wiktionary_ja.json --dump-date 2026-11-01
PYTHONPATH=backend .venv/bin/python -m pytest backend/tests -q
```

元ファイルは [Kaikki raw配布](https://kaikki.org/jawiktionary/rawdata.html) から取得。配布URLは更新されるため、同じ索引を再現するには同じスナップショットのgzipが必要。元gzipのSHA-256を索引に保存。出典とCC BY-SA 4.0の表示は [索引のREADME](../data/lexicons/README.md) を同梱。派生索引はGit管理、元データは対象外。

## fixed_compounds

途中で切ってほしくない、一つの意味として扱う表現。形態素境界にまたがっても、連続した形態素の表記を結合したものが登録語と完全一致すれば結合する。長い登録語を優先する。現在の補正後は名詞的な意味のまとまりとして扱い、通常ルールで後続の助詞・助動詞を付ける。

外部辞書が拾わない表現を優先させたい場合に使う。現行の「拍子抜けして」は外部辞書で結合するため、手動登録は不要。

登録語を部分文字列検索してどこでも置換するものではない。Sudachiが既にさらに長い一形態素にした場合、その内部を切って登録語を探す機能はない。全種類の活用・表記ゆれを自動生成する機能もない。辞書を大きくすれば無条件に高精度になるわけではない。

## 短い修飾句と述語

短い名詞の連なりは、名詞間の格助詞「の」も含めて一つにできる。「前の席の子から」「小さな星の形が」が例。動詞などに続く「とき／時」は直前のコマに付ける。「消えていた」など、先頭が動詞「消える」のまとまりは選択できる。

## non_wager_connectors

連続する形態素が登録した接続表現と一致した場合、優先して枠なしのまとまりにする。本文の文字は残す。既に一形態素の内部に含まれる場合は、そこだけを切り出せない。

例：「代わりに」は選べないが、「代わりが」は登録されていないため通常判定のまま選べる。すべての「代わり」を一律に除外しない。

同じ語を両方の一覧へ登録した場合、最終的な非選択指定が優先する。基本的には意図を明確にして重複登録を避ける。

## 追記手順

1. 実際の全文と、望む区切り・可否を控える。
2. 対象を結合したいのか、枠なしにしたいのかを決めてJSON配列へ追加。
3. 同じ表現を重複登録しない。空文字・空白を含む語は禁止。versionは現在1。
4. `backend/tests/test_segmentation.py`／`test_analysis.py` に実際の失敗例と、誤って変えてはいけない対比例を追加。
5. pytestで確認し、元本文の完全復元・start/end一致も保つ。
6. `.venv/bin/python scripts/precompute_starter_analysis.py` で開始文100件の区切りを再生成し、バックエンドを再起動して読み直す。辞書はプロセス内でキャッシュされる。
7. 新しいゲーム・本文版で確認。途中の保存済みUnit IDは書き換えない。

辞書例外を足すたびに、単なるリスト一致テストだけでなく、文の中で意図した区切りと選択可否になることを確かめる。

## 入力不正時

キーの過不足、未対応version、重複、空文字、空白、文字列でない要素を検査する。不正な辞書を黙って無視しない。JSONの書式・ファイル欠落も例外になる。デプロイ前テストで検出し、稼働中の辞書を未検証の内容で上書きしない。

## 制約と次の候補

品詞＋辞書は文脈の意味を完全には読まない。「代わりに」という関係自体を賭けたくなる場面が将来あり得るが、現在はユーザー指定を優先して枠なし。意味ある動詞の取りこぼし、形式名詞の過剰選択は残る。

次は実プレイの正解例を蓄積し、境界・可否を別々に測る。文節解析やGeminiによる文脈判定は未採用の候補。モデル追加や呼出増加を辞書導入の必須条件にしない。

Dockerは補正JSON・索引と帰属表示を明示COPYする。辞書は起動時に読み込み、無い・壊れている場合は起動失敗とする。ファイル名・配置を変えたらDockerfileと参照パスも更新する。
