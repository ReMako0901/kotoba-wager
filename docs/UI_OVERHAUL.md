# UI全面改修：現行レイアウトに拘らない再設計

ユーザーの指示（2026-11-18）：「今あるUIを全面的に修正して。
今あるやつに拘らなくていいから、持ってる力全てを使って
よくして」。直前の固定フレーム化（UI_LAYOUT.md）は出発点で
あって、守るべき正解ではない。視覚設計・レイアウト・
コンポーネント構成は自由に組み替えてよい。

## 参考資料：現行画面の実況（390×844で撮影し目視した記録）

画像は渡せないため、撮影を目視した所見を文章で渡す。

- **タイトル**：上部にステージ（肖像52px＋名札＋台詞1〜2行）。
  その下は大きな空白が続き、中段にゲーム名（明朝の大見出し
  2行＋「（仮称）」）と一文のキャッチ、ボタンは「遊び方」
  （白）と「はじめる」（赤）の2つ。画面下半分はほぼ空白で、
  間延びしている
- **物語選び**：ステージの下に見出し「物語を選ぶ」、「自分で
  物語を入力」「別の候補を見る」の2ボタン、物語カードが
  縦に並ぶ（ジャンル小字＋タイトル＋本文3〜4行）。カードは
  罫線だけの無地で、並びにリズムがない
- **言葉選び**：ステージ（76px）の下に「第N章 タイトル」の
  1行、中央に原稿用紙（10行×列は文章量次第、32pxマス。
  短い文章だと用紙の左側に空マス列が残る）、下端に操作バー
  （左：報酬ボタン「心の声・1個 変更」、中：個数とクリア、
  右：「ギャンブルを選ぶ」）。用紙の上下に大きな空白が
  あり、用紙が画面の主役になりきっていない
- **ギャンブル選択モーダル**：白い箱に「どのギャンブルに
  する？」、初心者／上級者のタブ、種目ボタンが縦並び。
  機能は足りているが装飾は皆無
- **ギャンブル中（じゃんけん）**：ステージの台詞が種目別の
  ものに替わり、中央に種目名だけが大きく出て、手のボタン
  3つが下端バーに並ぶ。中央の広大な空白に種目名が浮いて
  いるだけで、対決の場の感じが薄い
- **結果**：ステージに反応台詞、「第2版・勝利」の1行、
  中央に原稿用紙（紙の重なりと右下のめくり矢印つき）、
  下端バーに「どこが変わった？」と「次は何をねらう？」。
  構成は悪くないが、用紙上下の余白と、勝敗の祝祭感の
  なさが物足りない

共通の不満：余白が「間延び」にしかなっていない、画面
ごとの見せ場がない、置いただけの印象。逆に良い所：
視線の流れ（上→原稿→下のバー）は一方向で迷わない、
文字情報は最小限で済んでいる。

## 自由に変えてよいもの

- レイアウト、余白、タイポグラフィ、色使い（原稿の白・
  明朝・モノクロ＋赤線の文法の範囲で）、コンポーネントの
  分割や統合、CSS の構成、アニメーションと演出
- ステージの見せ方（大きさ・位置・肖像の使い方）も、
  常駐が守れるなら変えてよい

## 変えてはいけないもの（不変条件）

- ゲームの流れ：報酬3択ポップアップ→言葉選択→ギャンブル
  選択→ギャンブル開始→結果反映（repo の AGENTS.md が正）
- 表示しないもの：勝率の数字、強さ・変化量などのメタ情報、
  遊び方の説明文、状態文。説明はUIとアニメーションで見せる
- アノマは常時表示で、全場面で喋る（場面別セリフプールと
  確定台詞の優先順位は現行の仕組みを維持）。表情プールと
  切り替え（じわっとクロスフェード、瞬き、呼吸）も維持
- 原稿用紙：マス32px・10行固定、横スクロールのみ、文字は
  先頭から連続して詰める、結果は最初の変化箇所が文脈ごと
  見える。めくりは角つかみの斜めドラッグ
- ギャンブルは全てプレイヤー本人が操作する（自動進行なし）
- 「つづき」は無い状態を維持。バックエンドとAPI契約は
  変更しない。確率・抽選・保存も変更しない
- スマホ縦画面が主対象。ゲーム画面はスクロールなしで
  収まるのが望ましい（物語選び等の閲覧画面は内部
  スクロール可）

## 進め方

1. 監査画像と現行コードを見て、直す価値の高い順に
   自分で判断して全面改修する
2. 既存テストは原則維持。UI構造の変更でテスト側の追随が
   必要な場合は、不変条件を守る形で直す（勝率・メタ情報・
   つづき不在の確認は落とさない）
3. 完了したら docs の状態記録を実態に合わせる
