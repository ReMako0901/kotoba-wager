# UI全面改修：現行レイアウトに拘らない再設計

ユーザーの指示（2026-11-18）：「今あるUIを全面的に修正して。
今あるやつに拘らなくていいから、持ってる力全てを使って
よくして」。直前の固定フレーム化（UI_LAYOUT.md）は出発点で
あって、守るべき正解ではない。視覚設計・レイアウト・
コンポーネント構成は自由に組み替えてよい。

## 参考資料

- `docs/ui-audit/` に現行画面のスマホ幅（390×844）撮影を
  入れた（タイトル／物語選び／言葉選び／ギャンブル選択
  モーダル／ギャンブル中／結果）。まず全部見て、悪い所を
  自分の目で掴むこと
- 既知の不満：原稿の周りの余白が広く間延びする、全体に
  「置いただけ」の印象で画面ごとの見せ場がない

## 自由に変えてよいもの

- レイアウト、余白、タイポグラフィ、色使い（原稿の白・
  明朝・モノクロ＋赤線の文法の範囲で）、コンポーネントの
  分割や統合、CSS の構成、アニメーションと演出
- ステージの見せ方（大きさ・位置・肖像の使い方）も、
  常駐が守れるなら変えてよい

## 変えてはいけないもの（不変条件）

- ゲームの流れ：報酬3択ポップアップ→言葉選択→ギャンブル
  選択→ギャンブル開始→結果反映（repo の AGENTS.md が正）
- 表示しないもの：勝率の数字、強さ・変化量などのメタ情報、
  遊び方の説明文、状態文。説明はUIとアニメーションで見せる
- アノマは常時表示で、全場面で喋る（場面別セリフプールと
  確定台詞の優先順位は現行の仕組みを維持）。表情プールと
  切り替え（じわっとクロスフェード、瞬き、呼吸）も維持
- 原稿用紙：マス32px・10行固定、横スクロールのみ、文字は
  先頭から連続して詰める、結果は最初の変化箇所が文脈ごと
  見える。めくりは角つかみの斜めドラッグ
- ギャンブルは全てプレイヤー本人が操作する（自動進行なし）
- 「つづき」は無い状態を維持。バックエンドとAPI契約は
  変更しない。確率・抽選・保存も変更しない
- スマホ縦画面が主対象。ゲーム画面はスクロールなしで
  収まるのが望ましい（物語選び等の閲覧画面は内部
  スクロール可）

## 進め方

1. 監査画像と現行コードを見て、直す価値の高い順に
   自分で判断して全面改修する
2. 既存テストは原則維持。UI構造の変更でテスト側の追随が
   必要な場合は、不変条件を守る形で直す（勝率・メタ情報・
   つづき不在の確認は落とさない）
3. 完了したら docs の状態記録を実態に合わせる
