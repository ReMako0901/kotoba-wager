# 文章自動生成（アノマの質問から物語を作る）実装仕様

ユーザーの設計決定（2026-11-27）:

- ゲーム開始の既定の流れにする。オープニングの後、アノマが質問して、
  答えから物語を生成して始める。
- 右下に「プリセットの文で始める」ボタンを置き、押すと従来の
  プリセット選択画面へ行く（自分で入力も従来通りそちらから）。
- 質問は名前込みで3問。最初の質問は名前で固定、残り2問はプールから
  ランダム（重複なし）。
- 名前は物語に登場させる。DBに保存するときも、名前は認識できる形で
  そのまま入れる（将来、過去のプレイヤーの言葉がOPで渦巻く演出を作る
  ため。その表示のときに「私」等へ置き換えるのは将来の話で、今回は作らない）。
- 答えが短かったら、もう一文だけ深掘りする（その質問について1回だけ）。

## 質問フロー（フロント）

- オープニング終了後、物語選択ではなく質問画面に入る。
- アノマのダイアログ（ゲーム中ダイアログ板と同じ意匠）で1問ずつ聞く。
  導入の第一声は「まず、あなたのことを教えてくれる？」。
- 質問プール（名前以外）:
  今日あったこと／どこから、どうやって来たのか／今の気分／好きなもの／
  今日食べたもの／最近気になっていること／行ってみたい場所。
  文面はアノマの口調で用意する（sceneDialogue 相当の置き場に定数で）。
- 回答はページ上の入力欄＋「答える」ボタン。1問ごとに進む。
- 短い回答（10文字未満を目安、実装時に定数化）のときは、アノマが
  「もう少しだけ、教えてくれる？」と深掘りを1回だけする。
  深掘りの答えは元の答えに足して扱う。深掘りは各質問1回まで。
- 入力欄の近くに小さく注意書き: 個人が分かること（住所・学校・連絡先など）と
  重い話題は避けてほしい旨。アノマの導入でも軽く触れる。
- 右下に「プリセットの文で始める」ボタン（小さめ、スキップと同じ格）。
  押したら従来の物語選択画面へ。質問の途中でも押せる。
- 3問終わったら生成待ち（既存の生成待ち表示）→ 生成された物語で
  セッション開始（第1章として通常フローに入る）。

## 生成（バックエンド）

- 新規エンドポイント POST /api/stories/generate
  リクエスト: { name, answers: [{question, text}] }
- 画面表示用の個人情報パターン（メールアドレス、電話番号らしき数字列）は
  サーバーでも検査し、見つけたら 422 で「その内容は使えない」旨を返す。
- Gemini で { title, intro, text } を生成する。条件:
  - 主人公はプレイヤーの名前で登場させる（一人称の語りの中に名前が入る形）
  - intro は従来形式（1〜2文、賭け対象にしない導入）
  - text は従来の自作入力と同じ範囲（20〜100字目安）、賭けられる言葉が
    3つ以上入るように書く
  - センシティブな話題（暴力・性的・個人情報・重い相談ごと）は扱わない
    ようプロンプトで明示する
  - 呼び出しは既存の Gemini 経路・日次上限に含める
- 生成後に既存の解析で賭け可能単位数を確認する。3未満なら1回だけ
  条件を強めて再生成し、それでも駄目なら固定の予備文（既存の予備文の
  仕組みに合わせる）で開始する（勝敗と同じく、失敗しても遊びは止めない）。
- 保存: Firestore に generated_stories コレクションを作り、
  { name, answers, title, intro, text, created_at } を保存する。
  セッションと紐づけられるよう、返却値に生成IDを含め、フロントは
  セッション作成時にそれを渡し、セッション側にも生成IDを残す。
- セッション開始は既存の custom_text 経路を使う。タイトルも使えるよう
  CreateSession に任意の title を追加する（custom のときだけ有効、
  未指定なら従来の「自分の物語」）。

## テスト・検証

- バックエンド: 生成エンドポイントのテスト（Gemini はモック。
  検証→再生成→予備文の分岐、個人情報パターンの 422、保存の呼び出し）。
- フロント: 質問フローのテスト（3問の順序、名前固定、深掘りは1回だけ、
  プリセットボタンで選択画面へ）。
- 文言（質問・深掘り・注意書き）は新規に作る分は最小限にし、
  作業メモに一覧を残す（確定済みの台詞は変えない）。

## 進め方

- 作業メモ docs/WORKLOG_STORYGEN.md を随時更新する。
- コミットしない。CHANGELOG / STATUS / CURRENT_INSTRUCTIONS は触らない。
- 既存の不変条件（AGENTS.md）は全て維持する。
